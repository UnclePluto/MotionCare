# 患者游戏难度自由选择设计

## 1. 已确认需求与决策替代

用户明确将此前“患者只能降低难度，调整时必须选择反馈原因”变更为：

- 仅在开始游戏前调整，简单、中等、困难三档均可选择。
- 可以高于或低于指导老师设定的难度。
- 点击档位立即生效，无需填写原因、提交反馈或再次确认。
- 使用不同颜色凸显三档，当前选中档位清晰可辨。

用户已确认采用常驻的三档按钮，以及“处方作为进入时默认值、调整仅用于本次训练、保留历史反馈”的对话设计。

本 spec 获得书面确认后，替代两份 2026-05-16 游戏设计中涉及难度上限、调难原因必填和原因选择界面的要求，包括 2026-09-07 的相关更新。旧文档保留历史，通过追加指向本 spec 的决策更新说明消除冲突。Excel 档位参数继续作为玩法规则来源。

## 2. 范围

覆盖颜色顺序记忆、图案顺序记忆、反应抑制、分类转换、声音辨别、拼图，复用现有游戏会话准备页面。微信小程序与患者 H5 使用同一交互规则。

本次不增加训练中切换入口、不保存患者长期难度偏好、不改变医生处方版本，不修改六款游戏的难度参数、题目文案、展示时长、语音素材或签名素材访问机制。发布版本号与发布操作不属于本 spec 的实施验收条件。

## 3. 交互流程

1. 进入游戏准备页时，使用处方动作的难度作为当前选择；异常值沿用现有归一化规则，回退到简单。
2. 保留“指导老师设定难度”“本次训练难度”及当前档位规则说明。
3. 在规则说明下常驻展示简单、中等、困难三个等宽按钮，所有档位均可点击。删除“降低难度／收起难度选项”和“当前已是最低难度”逻辑。
4. 点击任意档位后，同步更新选中状态、本次难度文字和该档规则说明。该选择立即成为下一次开始训练使用的难度。重复点击当前档位不产生额外操作。
5. 删除反馈原因面板、四个原因选项、其他说明输入框，以及所有原因必填校验和相关错误提示。不增加保存按钮、确认弹窗或成功提示。
6. 三档按钮始终可见，因此恢复处方档位也通过点击对应档位完成，移除原先独立的“恢复指导老师设定”按钮。
7. 展示简短说明“仅用于本次训练”，说明选择的有效范围。
8. 点击原有“开始训练”后，出题与结果记录使用最终选中的档位。图片准备等现有开始门禁继续生效，取消反馈不意味着跳过素材准备。
9. 训练开始后本轮难度固定；页面隐藏、恢复、暂停和继续沿用现有会话逻辑。退出后重新进入训练时重新取处方默认难度。

例如：处方为简单，患者点击困难后，准备页立即显示困难及对应规则，可直接开始困难训练；处方为困难，点击简单可同样直接开始。整个流程均不要求原因。

## 4. 按钮视觉与可访问性

使用颜色表达档位，同时以文字和勾选表达选择状态，不只依赖颜色。

| 档位 | 色彩角色 | 未选中背景 | 未选中文字及边框 | 选中背景 | 选中文字 |
| --- | --- | --- | --- | --- | --- |
| 简单 | 青绿 | `#ecfdf5` | `#0f766e` | `#0f766e` | `#ffffff` |
| 中等 | 蓝 | `#eff6ff` | `#1d4ed8` | `#1d4ed8` | `#ffffff` |
| 困难 | 橙 | `#fff7ed` | `#9a3412` | `#9a3412` | `#ffffff` |

- 当前档位使用实色背景、白色文字和勾选标记，保留 `aria-pressed`。
- 档位颜色仅表示难度分类，不使用禁用、错误或危险操作的图标与提示。
- 三档采用等宽三列，按钮尺寸不随选中状态变化；勾选区域预留空间，避免选择时文字跳动。
- 沿用页面现有字体、圆角和间距体系，点击区域在实际渲染后至少为 44×44 CSS 像素。
- 在 320、375、414 CSS 像素宽度下，文字完整、无重叠、无横向溢出。规则说明自然换行，不挤压按钮。
- 文字与背景对比度至少 4.5:1；H5 键盘聚焦时有可见轮廓。

## 5. 状态、数据与兼容

### 患者端

继续使用现有难度状态和游戏规则说明函数；移除难度上限判断、低档位列表、原因状态与引用、原因选项常量及只服务于反馈的样式。最终开始操作以用户刚选中的值初始化会话，连续快速切换后点击开始也必须使用最终档位。

范围集中在 `miniapp/src/pages/game-session/index.tsx`、`gameDifficulty.ts`、对应测试及 `miniapp/src/app.scss`。不为本变更拆分整个游戏页面或重构出题器。

### 结果记录

继续复用现有记录协议：

- `form_data.difficulty`：本次实际难度。
- `raw_detail.prescribed_difficulty`：进入时对应的处方难度。
- `raw_detail.difficulty_adjusted`：实际难度是否与处方难度不同；提高与降低都可为 true。
- `raw_detail.difficulty_adjust_reason`：新版本创建的记录统一为空字符串，保留字段以兼容现有类型和接口，不填入虚构原因。

历史记录及已缓存待补传记录保持原内容，包括其中已有的原因。正常上传和失败补传均需保留新训练实际选中的难度。

### 后端与管理端

本次不新增数据库字段或 API，不改医生开方入口。现有后端允许保存实际难度和原始详情，现有管理端“调难原因”列将空值显示为“—”，继续显示历史原因。实施时通过针对性的记录契约回归确认“提高难度且原因为空”可正常保存，不扩展无关后台页面。

## 6. 验证与验收

### 行为与记录

- 六款游戏准备页均常驻三档，处方默认简单、中等、困难时均完整展示，默认选中正确。
- 处方简单可切到困难，处方困难可切到简单，均无需原因即可开始；用实际出题参数证明选择生效，而不只断言标签变化。
- 快速连续切换使用最终档位；重复点击同档保持稳定；切回处方档位后调整标记为 false。
- 准备页无反馈选项、输入框、原因校验、难度上限报错或额外确认步骤。
- 上调、下调与未调整记录的实际难度、处方难度、调整标记正确，新记录原因字段均为空。
- 新记录的失败补传保留所选档位，历史原因与历史待补传数据仍可读取和使用。
- 训练中没有难度切换入口；退出重进恢复处方默认值。
- 既有图片未就绪门禁、隐藏恢复、2 秒序列展示和其他游戏规则回归通过。

### 视觉

- 三种默认状态和三种选中状态均检查文字对比度。
- 在三个指定视口检查等宽按钮、勾选标记、长规则说明和点击区域；生成实际页面截图供用户查看。
- H5 浏览器和微信构建的验证结果分别记录，不把浏览器截图或开发工具结果表述为微信真机通过。

### 工程门禁

运行受影响的页面、难度和记录契约测试，再按项目要求完成后端测试、管理端测试/lint/build、小程序测试与微信构建及包体检查。任何既有警告、无法执行的真机验收均如实记录。此文档本身不代表实现、测试或发布已完成。
