# 微信小程序认知游戏大图展示与选择反馈设计

## 1. 背景

当前颜色顺序记忆和图案顺序记忆在记忆阶段把完整序列同时放入四列网格。颜色块和图案只有按钮大小，患者难以集中观察；当连续两项内容相同时，画面没有明确切换边界，患者可能把两项误认为一项。

其他游戏还存在相近但不完全相同的问题：

- 声音辨别的图片偏小，试听过的卡片没有在播放后翻回背面，作答反馈也没有稳定落在所选卡片上。
- 数字抑制和分类切换只显示网格下方的泛化短句，患者看不到具体哪个选项被判定为正确或错误。
- 拼图已有足够大的预览和操作区，只需要更明确的临时选中效果。
- 分类切换的 `scene` 选项不互斥，部分颜色元数据与实际图片不一致，可能把合理答案记录为错误。

本设计按玩法分型统一交互状态，不强迫六款游戏使用同一种布局。

## 2. 已确认决策

1. 颜色和图案顺序在记忆阶段改为中央单项大舞台，单个内容约占可用屏幕高度三分之一。
2. 顺序项逐个展示；相邻两项之间固定插入 `500ms` 的“下一项”过渡，不压缩每项原有观察时间。
3. 过渡期间隐藏上一项和下一项，并同步更新“第 n/N 项”，确保连续相同内容也能被识别为两项。
4. 顺序作答阶段保留多槽位 UI。患者每选一步，对应槽位显示实际选择，并立即叠加该位置的 `✓` 或 `✕`。
5. 顺序作答不允许撤销。单步对错只用于反馈，整题得分仍按完整序列原规则计算。
6. 声音辨别保留稳定卡片网格，不改成中央单卡舞台；放大卡片内图片。
7. 声音试听时只有当前卡翻到正面，正面只显示图片，不显示类别、编号或其他小字；播放完成后翻回背面，再处理下一张。
8. 声音作答正确时，所选卡片翻到正面显示图片；作答错误时，所选卡片保持背面，只显示红色选框，不揭示正确卡片。
9. 声音选择态和本题反馈框保留到本题结束，再进入下一题。
10. 拼图只增加第一块的点击选中效果；第二块点击并完成交换后立即清除。拼图其他行为暂不修改。
11. 数字抑制和分类切换保留现有布局，在具体选项上显示本题对错反馈。
12. 分类切换暂时停用含义不互斥的 `scene` 规则，并按实际图片核对、修正颜色元数据。
13. 每题结果反馈固定保留 `1000ms` 后进入下一题。
14. 后端接口、训练记录结构、评分公式、难度档位、整场倒计时、上传与补传逻辑保持不变。

## 3. 目标与非目标

### 3.1 目标

- 让认知衰弱或低视力患者能清楚识别每个记忆项和每次选择结果。
- 为连续相同的颜色或图案建立明确的时间边界。
- 统一“未选择、已选择、正确、错误”状态语言，同时保留各游戏的训练目标。
- 修复分类题中会产生非客观答案的现有规则。
- 保持现有评分、逐题数据与训练上传主链路稳定。

### 3.2 非目标

- 不重做游戏算法、难度曲线或后端数据模型。
- 不改变数字抑制的选项数、三列结构和超时。
- 不给拼图增加常驻原图、自动提示、正确位置编号或逐次对错判定。
- 不新增声音整轮重试、手动逐卡试听或新的音频控制流程。
- 不改准备页、结果页和公共暂停/静音/提前结束控制条。
- 不重新生成或替换游戏图片、声音资源。

## 4. 统一交互模型

游戏页面继续由 `miniapp/src/pages/game-session/index.tsx` 承载。UI 状态按玩法分为四类：

| 类型 | 游戏 | 状态流 |
| --- | --- | --- |
| 顺序记忆 | 颜色顺序、图案顺序 | 单项展示 → 500ms 过渡 → 下一项 → 槽位作答 → 逐槽位反馈 → 整题结束 |
| 卡片记忆 | 声音辨别 | 背面网格 → 当前卡翻开试听 → 当前卡翻回 → 下一卡 → 全背面作答 → 卡片结果反馈 |
| 单次选择 | 数字抑制、分类切换 | 展示题目 → 点击选项 → 具体选项反馈 → 整题结束 |
| 两步选择 | 拼图 | 选择第一块 → 显示临时选中态 → 点击第二块并交换 → 清除选中态 |

不同类型共享以下语义：

- `idle`：可作答但尚未选择。
- `selected`：患者已点击，当前回合锁定或正在等待第二步。
- `correct`：使用对勾、成功语义色和明确反馈文案共同表达。
- `wrong`：使用叉号或红色选框，并配合错误反馈文案；不能只依赖颜色。
- `settling`：结果保持 `1000ms`，期间禁止重复点击并等待下一题。

## 5. 颜色与图案顺序

### 5.1 记忆大舞台

记忆阶段不再渲染完整序列网格，只渲染当前项：

- 大舞台在可用页面区域内约占屏幕高度三分之一，并保留安全区和底部控制条空间。
- 颜色项显示大面积纯色/现有渐变块及颜色名称，不能只显示颜色。
- 图案项使用 `aspectFit` 放大图片并保留图案名称。
- 舞台上方显示“第 n/N 项”。
- 候选按钮在记忆阶段保持禁用，避免患者提前作答。

### 5.2 项间过渡

每项按当前难度的 `revealMs` 完整展示。结束后进入固定 `500ms` 过渡：

1. 完全隐藏当前颜色或图案及名称。
2. 舞台显示短暂、低刺激的“下一项”提示。
3. 更新序号。
4. `500ms` 结束后显示下一项。

过渡不使用弹跳或大幅位移动画。系统要求减少动态效果时，仍保留静态空档和“下一项”文字，不能直接跳过时间边界。

### 5.3 作答槽位

记忆结束后恢复现有多槽位和候选按钮：

- 未作答槽位显示顺序编号。
- 每次点击把实际选择填入当前槽位。
- 颜色槽位显示颜色及名称；图案槽位显示图片及名称。
- 将该选择与目标序列同位置比较，立即在槽位上叠加 `✓` 或 `✕`。
- 已填槽位不可修改；答错后继续完成剩余序列。
- 最后一个槽位完成时，继续调用现有完整序列判定与逐题记录逻辑。

## 6. 声音辨别

### 6.1 试听阶段

声音卡继续使用稳定双列网格，卡片位置从本轮开始到结束不变：

- 放大 `.game-card-image` 在声音卡中的占比，使图片成为正面主体。
- 当前试听卡翻到正面并播放对应声音。
- 正面只显示图片，不显示类别、小字标签或编号。
- 播放成功或失败结束后，当前卡都恢复背面；播放失败继续使用现有错误提示。
- 当前卡翻回完成后再开始下一卡，避免两张卡同时处于正面。
- 试听结束后所有卡保持背面，系统播放目标声音并进入作答。

### 6.2 作答与反馈

- 作答阶段所有卡显示稳定背面编号。
- 点击后立即锁定本题，禁止第二次选择。
- 如果选择正确，所选卡翻到正面显示图片，并显示正确反馈框。
- 如果选择错误，所选卡不翻转，只增加高对比红色选框，并显示错误反馈框。
- 错误时不翻开或额外标记正确卡片。
- 结果保持 `1000ms`，然后开始下一题并清除所有结果状态。

## 7. 数字、分类与拼图

### 7.1 数字抑制

- 保留现有大数字、三列网格、选项数和超时。
- 点击正确项时在该按钮显示对勾和成功态。
- 点击错误项时在该按钮显示叉号和错误态。
- 本题锁定并保留结果 `1000ms`，不修改判分。

### 7.2 分类切换

- 保留“当前规则 → 中央图片 → 选项按钮”的布局。
- 在现有分类舞台内适当放大图片主体，但不扩展为新的记忆阶段。
- 选项反馈与数字抑制一致。
- `scene` 从所有难度的可选规则中移除，直到未来有互斥、经过人工验收的独立场景素材集。
- `color` 元数据必须以图片中目标物体的主要颜色为准；本期固定映射为：菠萝=黄色、小鸟=蓝色、火车=蓝色、鼓=红色、电话=蓝色。
- `kind` 规则保持不变。

### 7.3 拼图

- 第一块点击后显示高对比选中边框、轻微缩放或选中标记。
- 选中效果不能遮挡需要辨认的主要拼图内容。
- 点击第二块并执行交换后，立即清除选中态。
- 再次开始新一轮时不得残留上一轮选中状态。
- 不新增对勾、叉号、正确位置提示或完成阶段视觉。

## 8. 计时、暂停与状态清理

### 8.1 顺序记忆计时

顺序展示需要记录：

- 当前序列索引。
- 当前处于 `item` 还是 `transition`。
- 当前阶段剩余毫秒数。

暂停时保存上述状态并停止计时器；恢复后从当前阶段剩余时间继续，不跳项、不重复项，也不重新开始整段序列。

### 8.2 声音与作答反馈

- 暂停时沿用现有音频停止和阶段恢复逻辑。
- 新一题开始、主动结束、超时或切换游戏时必须清除选择结果、翻牌结果和反馈计时器。
- 结果保持阶段不应重复写入逐题结果或重复调度下一题。

## 9. 数据与接口

本设计不新增后端字段，也不修改 `TrainingRecord.form_data.raw_detail` 结构。

- 顺序游戏仍提交原目标序列、患者完整选择和整题 `correct`。
- 单步 `✓/✕` 是前端即时反馈，不新增上传字段。
- 声音游戏仍按具体 `soundId` 判定，不上传图片路径或卡片正反面状态。
- 拼图仍只在完成时记录一轮成功；临时选中态不进入数据。
- 分类规则停用 `scene` 只影响前端出题集合，不改变结果接口。

## 10. 异常与无障碍

- 颜色名称、图案名称、对勾/叉号和反馈文案共同传达状态，不能只靠红绿颜色。
- 声音答错虽然按用户确认只显示红色选框，但同时必须保留“选择错误”反馈框。
- 声音图片加载失败沿用现有卡片背面，不把空白正面视为有效展示。
- 音频播放失败时不留下正面卡片，恢复背面并使用现有错误提示。
- `prefers-reduced-motion` 下取消翻转动画和缩放动画，但保留正反面、选中、正确和错误的最终静态状态。
- 新增视觉区域不得被底部固定控制条或安全区遮挡。

## 11. 代码影响范围

预计修改：

- `miniapp/src/pages/game-session/index.tsx`：新增顺序展示阶段、结构化选择结果和各游戏渲染状态。
- `miniapp/src/app.scss`：大舞台、过渡提示、作答槽位、声音卡正反面和游戏反馈样式。
- `miniapp/src/pages/game-session/colorSequence.ts` 及测试：如需要，承载可测试的顺序展示阶段辅助逻辑。
- `miniapp/src/pages/game-session/patternSequence.ts` 及测试：图案序列展示与同项过渡测试。
- `miniapp/src/pages/game-session/soundDiscrimination.ts` 及测试：声音卡展示状态与结果状态辅助逻辑。
- `miniapp/src/pages/game-session/categorySwitch.ts` 及测试：停用 `scene`、修正颜色元数据并收紧出题集合。
- 相关页面测试：覆盖状态接线、计时清理和下一题过渡。

不应修改：

- 后端模型、migration、API serializer 或训练记录接口。
- 医生端页面。
- 游戏总分公式、难度档位、上传补传策略和逐题结果结构。

## 12. 测试与验收

### 12.1 自动化测试

- 颜色和图案连续相同项之间必定进入 `500ms` 过渡状态。
- 每项原有 `revealMs` 不因过渡缩短。
- 暂停发生在展示或过渡时，恢复后从剩余时间继续。
- 顺序槽位依次填入实际选择，按位置生成正确/错误视觉状态，且不允许撤销。
- 声音试听任何时刻最多只有一张正面卡；播放结束后翻回。
- 声音答对翻开图片，答错保持背面并标红；新一题清除结果。
- 拼图第一块产生选中态，第二块交换后清除。
- 数字和分类选项显示对应结果，并在 `1000ms` 后进入下一题。
- 分类出题不再生成 `scene`；颜色元数据与验收后的图片一致。
- 现有评分、暂停恢复、逐题数据、最终上传和补传测试继续通过。

### 12.2 构建与手动验收

至少执行：

```bash
cd miniapp && npm run test
cd miniapp && npm run build:weapp
```

在微信开发者工具和至少一台真机上检查：

- 简单、中等、困难三档颜色与图案顺序。
- 连续两个相同颜色、连续两张相同图案的 `500ms` 切换边界。
- 长序列作答槽位换行、图片清晰度和底部控制条遮挡。
- 4、6、8 张声音卡的图片尺寸、逐张翻回、正确翻开和错误红框。
- 拼图选择态在高细节图片上的可见性及交换后清除。
- 暂停、恢复、静音、超时和主动结束不会残留计时器或重复记录。

## 13. 风险与控制

- **总展示时间增长**：每个顺序间隔增加 `500ms`。这是已确认的可辨识性要求，不压缩患者观察时间。
- **长序列占屏**：记忆阶段只显示单项；作答槽位允许换行，但候选按钮和底部控制不得被推离可操作区域。
- **声音卡过大导致滚动**：只放大卡内图片，不改变稳定网格列数；真机验收困难档 8 卡和底部控制条关系。
- **异步音频竞态**：翻牌状态必须绑定当前轮次标识；迟到的播放回调不得修改新一题。
- **状态残留**：所有结果态、选中态和过渡计时器集中在新一题、结束、卸载与难度切换路径清理。
- **分类数据误判**：`scene` 在新素材经过人工验收前保持禁用，不能用相近词替换后继续上线。

## 14. 验收结论

设计完成的判断标准是：患者能在不依赖猜测的情况下区分每个记忆项、看清自己选择的结果，并且六款游戏原有训练目标、计分、数据记录和上传链路不发生变化。
