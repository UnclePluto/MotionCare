# 穿戴设备管理权限与录入优化设计

## 1. 问题与根因

医生可以通过研究录入页面打开任意已入组的 `ProjectPatient`，但穿戴设备接口复用了训练模块的
`accessible_project_patients()`。该函数会按患者主治医生、项目创建人或入组创建人过滤，导致
页面可见而设备状态接口返回 `No ProjectPatient matches the given query.`。

当前系统没有“医生属于某个项目”的关系。已确认规则是：所有医生和管理员都可以管理任意
已入组患者的穿戴设备；没有 `ProjectPatient` 入组关系的患者不提供绑定入口。

## 2. 权限规则

- 穿戴设备管理对象以已存在的 `ProjectPatient` 为准。
- 通过 `IsAdminOrDoctor` 鉴权的医生和管理员，可以查询、绑定、通信测试、响铃、解绑和执行
  设备管理命令。
- 不存在的 `ProjectPatient` 继续返回 404。
- 前端绑定入口继续只放在项目患者研究录入页，因此未入组患者不会出现入口。
- 不修改训练记录、视频、健康趋势和健康测量数据的既有查询权限。

## 3. 后端边界

穿戴设备模块新增独立的“可管理项目患者”查询，不再从训练模块复用
`accessible_project_patients()` 作为设备管理权限。

该查询用于以下设备管理链路：

- 项目患者设备绑定状态查询与设备绑定；
- 设备解绑；
- 设备管理列表中当前绑定患者的安全展示；
- 通信测试、响铃、主动测量、配置和手动同步。

健康测量点、日汇总、同步状态和项目汇总等研究数据查询继续沿用原有权限函数，本次不扩大
健康数据可见范围。

## 4. 前端行为

前端不新增页面或入口。现有 `ProjectPatientBindingCard` 只有获得真实
`ProjectPatient.id` 后才会渲染：

- 已入组患者正常显示绑定入口和设备状态；
- 未入组患者没有项目患者研究录入页，因此没有绑定入口；
- 修复后不再展示 `No ProjectPatient matches the given query.`。

原“设备台账”统一更名为“设备管理”，覆盖左侧菜单、页面标题和加载失败文案。路由继续使用
`/wearable-devices`，不做无收益的地址迁移。

设备管理列表增加“IMEI”列，并把搜索提示改为“搜索固定简码或 IMEI”。仅当历史设备的
`identifier_type="imei"` 时才在该列展示标识；其他历史标识显示为“—”，避免把 SN 或
`device_id` 误标成 IMEI。现有固定简码、型号、当前患者、通信与同步状态继续保留。

## 5. IMEI 单字段录入

新增设备弹窗只展示一个“IMEI”输入框。录入规则如下：

- 去除输入首尾空格后，必须是 15 位纯数字；
- 前端即时校验，后端执行相同的权威校验；
- 任意厂商下已经存在相同 IMEI 时，返回明确的“该 IMEI 已存在”错误；
- 提交成功后，列表立即展示新设备的 IMEI 和系统生成的固定简码。

新增接口正式支持只提交 `imei`，由后端映射并补全现有设备字段：

| 设备字段 | 创建值 |
| --- | --- |
| `provider` | `miwitracker` |
| `external_device_id` | 规范化后的 IMEI |
| `identifier_type` | `imei` |
| `model` | 空字符串，页面显示为“—” |
| `enabled` | `true` |
| `short_code` | 系统生成的未占用四位数字字符串 |

设备 API 响应和数据库模型继续保留原有完整字段，不清理历史设备。新增页面不再提交厂商、厂商
设备标识、标识类型或型号，不通过前端隐藏字段伪造默认值。

首次通信测试成功且设备型号仍为空时，系统使用厂商返回的非空型号补全 `model`，并在同次测试
中据此计算设备能力；已有非空型号不被自动覆盖。写入前必须确认厂商响应的设备标识与当前设备
一致，并拒绝超过模型字段长度上限的型号；校验失败时不更新设备状态、型号或能力。

现有固定简码生成规则保持不变：允许 `0007` 这类前导零，数据库唯一约束负责最终并发保护，
发生碰撞时重新生成；四位号码空间耗尽时明确阻止新增。

## 6. 错误与安全

- 未登录用户、患者端身份及其他非医生/管理员角色仍被 `IsAdminOrDoctor` 拒绝。
- 不存在的项目患者、设备或绑定记录继续使用 404，避免泄露无效资源细节。
- 设备冲突、已解绑、设备停用等既有业务错误语义保持不变。
- 本次不新增模型、字段或数据库迁移。

## 7. 测试与验收

自动化测试至少覆盖：

1. 医生不是患者主治医生、不是项目创建人、也不是入组创建人时，仍可查询已入组患者的设备绑定状态。
2. 上述医生可以用有效设备简码完成绑定，并能通信测试和解绑。
3. 不存在的 `ProjectPatient` 仍返回 404。
4. 未入组患者不能通过项目患者绑定接口建立设备绑定。
5. 只提交合法 IMEI 时，后端补全默认字段并生成唯一四位简码。
6. 非 15 位纯数字 IMEI 被前后端拒绝，重复 IMEI 返回明确错误。
7. 新增设备弹窗只展示 IMEI，列表展示 IMEI 与固定简码。
8. 菜单、页面标题和设备管理加载失败文案不再使用“设备台账”。
9. 既有穿戴设备测试、后端完整测试和前端绑定卡片测试继续通过。
10. 空型号设备通过通信测试识别型号后，可以使用该型号支持的远程命令。
11. 历史跨厂商重复 IMEI 被拒绝，历史非 IMEI 标识不会显示在 IMEI 列。

验收标准：生产环境中任一医生打开任一已入组患者的研究录入页时，设备状态正常返回；未绑定
设备时显示绑定入口，已绑定时显示设备信息与管理操作，不再出现权限不一致错误。

## 8. 非目标

- 不建立医生与项目的关联模型。
- 不改变患者主治医生字段。
- 不扩大训练、视频或健康研究数据的读取范围。
- 不给未入组患者增加穿戴设备绑定入口。
- 不修改小程序端。
- 不删除或重命名 `provider`、`external_device_id`、`identifier_type`、`model` 等历史字段。
- 不修改现有设备数据，也不要求历史设备标识全部转换成 IMEI。
- 不在创建时调用厂商接口探测设备型号。
