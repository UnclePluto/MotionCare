# 微信小程序肩部推举全屏录像与存储保护设计

## 1. 背景与问题

线上真机测试暴露出两类独立问题：

1. 录像页仍是卡片式滚动布局，没有达到全屏相机、画中画和画面内正倒计时的预期；此前完成的
   预览与画中画分支也尚未发布。
2. 旧录像流程调用微信 `saveFile` 时出现
   `the maximum size of the file storage limit is exceeded`，导致分段保存失败。

生产环境已有录像分段约 31 秒、38.7MB，约为 1.23MB/s。按这一实测量级，10 分钟录像约
740MB，无法在微信约 100MB 的持久化文件额度内完整离线保存。因此本设计不再尝试为整段训练
预留离线容量，而是采用“5 秒分段直传 + 有界本地缓冲 + 高低水位暂停恢复”。

本设计局部覆盖关联设计中的两项行为：

- 肩部推举录像从 15 秒分段改为 5 秒分段；
- 录像页从卡片式内容页改为全屏相机页。

示范视频预览、正倒计时、手动/自动结束、手机端训练时间语义、服务器分片合并与七牛最终视频
发布继续遵循关联设计，除本文明确修改外不变。

## 2. 已确认决策

1. 本期只修改微信小程序肩部推举录像流程，不修改患者 H5、医生端或其它训练动作。
2. 录像页使用全屏相机作为主画面，左侧固定正计时与倒计时，右上侧显示可收起示范视频，底部
   固定“结束训练”。
3. 点击“开始训练”后，必须先清理本小程序历史 `saveFile` 文件，并让患者等待清理与复核完成。
4. 存在待上传肩部推举会话时绝不清理其文件，优先进入现有补传流程。
5. 微信没有可用于本场景的真实手机剩余磁盘查询；预检以微信文件保存上限和
   `getSavedFileList` 返回的文件大小为依据。
6. 清理后可用持久化文件额度不足 65MB 时硬拦截，不允许强行开始。
7. 不再录制 3 秒校准片；容量保护使用真实待上传分段字节数，而不是处方时长乘固定码率。
8. 正式录像每 5 秒生成一个分段，生成后立即进入现有单并发上传队列。
9. 服务端确认分段上传成功后，立即尽力删除对应本地文件；删除失败不得把已确认分段重新计入
   待上传缓存。
10. 待上传本地分段达到或超过 65MB 时，在当前 5 秒分段安全结束后自动暂停录像。
11. 暂停时播放本地语音：“网络较慢，训练已暂停，请保持页面打开，等待视频上传。”
12. 暂停期间继续上传；待上传本地分段降到 10MB 以下后，播放本地语音：“视频上传已恢复，
    可以继续训练。”
13. 缓存恢复后不自动重新录像，由患者点击“继续训练”；暂停期间正计时和倒计时均不增长。
14. 两条语音资源内置在小程序包中，不依赖网络；语音播放失败只降级为文字提示。
15. 若微信在 65MB 前就返回真实磁盘不足或文件保存失败，立即进入相同暂停状态，不丢弃已经
    完成的分段。

## 3. 页面与交互

### 3.1 全屏录像页

录像页使用自定义导航和固定定位布局：

- 相机组件占满整个可用屏幕，不再渲染 hero、说明卡、录像指标卡或页面滚动区域；
- 自定义返回入口避开系统安全区域；
- 左侧计时卡固定显示“已训练”和“剩余”；
- 右上侧示范视频继续静音、循环播放，并保留右滑隐藏、左滑恢复；
- 底部固定“结束训练”或“继续训练”主按钮；
- 上传计数、网络慢、清理中和错误状态使用覆盖层或紧凑提示条，不挤压相机画面。

摄像头未准备好、权限被拒绝、清理中或空间不足时仍保留全屏容器，但显示明确的阻塞说明和
可执行按钮。录像启动成功前不显示运行中的正倒计时。

### 3.2 启动前清理与空间检查

患者点击“开始训练”后进入不可重复触发的预检流程：

```text
检查待上传会话
  -> 有待上传：进入补传页，不清理
  -> 无待上传：显示“正在清理历史录像，请稍候”
       -> getSavedFileList
       -> 等待全部删除操作结束
       -> 再次 getSavedFileList
       -> 计算 available = 100MB - remainingSavedBytes
       -> available >= 65MB：允许正式启动
       -> available < 65MB：拦截并提示重新清理或返回处方
```

文件删除部分失败时，不依据单次回调直接判定；必须重新获取文件清单，以复核后的剩余占用作为
唯一判断依据。文件清单接口失败时无法证明空间充足，安全起见拦截并允许重试。

清理和检查期间不创建服务端训练视频会话，不写 `training_started_at`，不启动正倒计时。页面
卸载后到达的异步结果必须失效，不得在新页面或新会话中继续启动录像。

目前小程序内只有肩部推举使用 `saveFile`，因此在不存在待上传会话时允许清理本小程序全部历史
持久化文件。以后其它模块若开始使用 `saveFile`，必须先引入文件归属登记，再缩小清理范围。

### 3.3 空间不足提示

启动前不足 65MB 时显示安全文案：

```text
录像空间不足
当前可用约 X MB，开始训练至少需要 65MB。
请点击“重新清理”后再试。
```

提供“重新清理”和“返回处方”，不展示微信原始英文错误，也不提供绕过入口。

## 4. 5 秒分段与有界缓存

### 4.1 分段上传

录像器的常规分段时长从 15 秒改为 5 秒。每个分段完成后按现有顺序执行：

1. 获取实际时长和字节数；
2. 写入当前会话清单；
3. 立即交给单并发上传队列；
4. 服务端确认后标记为已上传；
5. 尽力删除本地文件。

手动结束、自动结束、进入后台或达到相机安全截止时产生的有效尾段即使不足 5 秒，也继续按
现有最短有效尾段规则保存并上传。分段序号保持连续，服务端最终仍按序校验和合并。

### 4.2 缓冲字节口径

缓冲字节只统计“尚未获得服务端确认且仍依赖本地文件”的可上传分段：

```text
pendingLocalBytes = sum(sizeBytes of locally required, not server-confirmed segments)
```

上传中的分段仍计入，直到服务端确认；服务端已确认的分段即使本地删除失败也不再计入。仅有
临时路径但尚未持久化成功的失败分段同样计入，因为它仍占用本地资源并存在丢失风险。

### 4.3 高低水位状态

```text
recording
  -> 当前分段安全结束
  -> pendingLocalBytes >= 65MB
  -> buffer_paused（停止产生新分段，继续上传）
  -> pendingLocalBytes < 10MB
  -> buffer_ready（语音提示，等待患者点击继续）
  -> recording
```

达到高水位时不在分段中间强制截断；因此实际峰值可能比 65MB 多一个 5 秒分段，但仍保留约
35MB 的微信额度余量。高水位暂停和低水位恢复在同一轮状态中各只触发一次，避免语音重复和
状态抖动。恰好 10MB 时仍不可继续，必须严格低于 10MB。

## 5. 语音与文字告警

新增两条小程序包内本地音频：

- 暂停：“网络较慢，训练已暂停，请保持页面打开，等待视频上传。”
- 恢复：“视频上传已恢复，可以继续训练。”

播放由独立、可测试的肩部推举告警播放器负责，并遵守以下规则：

- 同一状态代次只播放一次；
- 新语音开始前停止旧语音；
- 页面卸载时停止并销毁播放器；
- 播放失败不改变录像、上传、暂停或恢复状态；
- 同步显示与语音一致的文字提示，保障静音设备和听障用户可用。

## 6. 状态与异常处理

| 场景 | 行为 |
| --- | --- |
| 存在待上传会话 | 不清理，进入补传页 |
| 清理部分失败但复核后可用不少于 65MB | 允许继续 |
| 清理后可用不足 65MB | 硬拦截，提供重新清理和返回处方 |
| 文件清单接口失败 | 硬拦截并允许重试 |
| 清理期间重复点击 | 复用同一任务，不并发清理或启动 |
| 清理期间退出页面 | 使异步结果失效，不创建会话 |
| 单个 5 秒分段上传失败 | 保留并重试，纳入缓冲字节 |
| 缓冲达到 65MB | 分段边界自动暂停并语音告警 |
| 缓冲降到 10MB 以下 | 语音提示，等待患者手动继续 |
| 65MB 前发生真实保存失败 | 紧急暂停并显示空间/文件错误 |
| 语音播放失败 | 只保留文字提示，业务流程继续 |
| 小程序进入后台 | 沿用自动暂停；返回后重算缓存，不自动继续 |
| 服务端已确认、本地删除失败 | 后台继续清理，不重新上传、不计入缓存 |
| 患者选择重新训练 | 先按既有规则终止旧会话并清理，再走预检 |

患者因缓冲暂停时不修改首次 `training_started_at`；暂停时长不进入有效录像时长，恢复后继续
基于已保存分段与当前活动分段计算正倒计时。

## 7. 组件边界

为避免继续扩大录像页职责，新增或收敛以下单元：

- 存储预检器：列出文件、等待清理、复核占用、计算 65MB 启动门槛；
- 缓冲水位纯函数：根据分段和服务端确认状态计算字节数，并给出 recording / buffer_paused /
  buffer_ready 转换；
- 告警播放器：只管理两条本地语音的播放、停止和销毁；
- 录像器：只把常规分段边界改为 5 秒并保持尾段语义；
- 录像页：协调预检、录像、上传、计时和覆盖层，不直接实现文件遍历或音频生命周期细节。

不新增后端模型或接口。后端继续接受正整数分段时长、连续序号和最终分段总数；实施时必须验证
10 分钟约 120 段、40 分钟最多约 480 段的校验、缺片响应和 FFmpeg 合并链路。

## 8. 测试与验收

### 8.1 自动化测试

- 清理等待所有删除完成后才复核并启动；有待上传会话时不清理。
- 可用空间小于 65MB 时拦截，恰好 65MB 时允许开始。
- 文件清单失败、部分删除失败、重复点击和页面卸载竞态均不会误启动。
- 录像器每 5 秒产生分段，下一段连续启动，有效尾段仍保存。
- 缓冲低于 65MB 不暂停，达到或超过 65MB 只暂停一次。
- 恰好 10MB 仍不可恢复，低于 10MB 才进入可继续状态。
- 暂停和恢复语音各只播放一次，播放失败不改变业务状态。
- 缓冲暂停期间正倒计时不增长，恢复后不重置。
- 服务端确认分段后立即清理，不再计入缓冲。
- 全屏相机、左侧计时、右侧画中画、恢复条和底部按钮结构正确。
- 后端覆盖大量连续短分段的结束校验、缺片反馈和处理任务输入。

### 8.2 微信开发者工具与真机

- iOS 与 Android 验证全屏相机、同层画中画、安全区域和底部按钮命中。
- 清理过程中有明确等待反馈，不假死、不创建训练会话。
- 模拟慢网和断网，验证 65MB 暂停、告警语音、10MB 以下恢复提示和手动继续。
- 语音在静音、来电中断、音频播放失败时能正确降级为文字。
- 训练完成后无已确认分段残留；异常退出后待上传文件仍可补传。
- 5 秒分段在 10 分钟和最长 40 分钟训练下能完成服务端合并与七牛发布。

## 9. 非目标

- 不支持整段训练完全离线保存；65MB 只提供有界网络抖动缓冲。
- 不恢复旧的客户端视频压缩流程。
- 不允许患者绕过启动前 65MB 检查。
- 不自动恢复录像；缓存恢复后仍由患者主动继续。
- 不修改示范视频来源、医生端分析、穿戴健康窗口或其它训练动作。
