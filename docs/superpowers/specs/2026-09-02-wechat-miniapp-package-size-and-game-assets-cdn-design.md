## 1. 背景与测量基线

当前微信小程序已经把 `pages/game-session` 配置为普通分包，并在进入游戏前调用
`wx.loadSubpackage` 展示下载进度。游戏分包中的 18 张 PNG 和 37 段游戏 M4A 使该分包接近
微信单分包 2 MiB 上限；最新合入的 5 段动作说明 M4A 又使主包增长约 1.03 MiB。

基于生产构建的原始文件字节数，当前基线为：

| 部分 | 体积 | 说明 |
| --- | ---: | --- |
| 主包 | 1,505.3 KiB | 其中 5 段动作说明语音占 1,028.4 KiB |
| `pages/game-session` 分包 | 1,887.3 KiB | 距 2 MiB 仅约 161 KiB |
| 全部代码包 | 3,392.6 KiB | 当前未触及总包上限 |
| 游戏图片 | 882.6 KiB | 18 张 384×384 PNG |
| 游戏音频 | 950.1 KiB | 37 段 AAC 单声道 M4A |
| 动作说明语音 | 1,028.4 KiB | 5 段 AAC 单声道 M4A，当前进入主包 |
| 游戏页面与逻辑 | 约 55 KiB | 分包去除图片和音频后的主体 |

另有两对运动训练网络提示音同时存在于 `features/motion-training` 和
`pages/shoulder-press`，二进制内容相同；当前构建只引用公共目录的一份，删除肩部推举目录下的
未使用副本只减少仓库冗余，不作为代码包体收益计算。

## 2. 目标

1. 将游戏分包控制在 1.3 MiB 以内，并为后续游戏素材预留至少 700 KiB 空间。
2. 将主包恢复到 1.2 MiB 以内，并为后续患者端能力预留至少 800 KiB 空间。
3. 图片资源加载失败不能让患者在缺少视觉刺激的情况下继续训练或提交不可比的研究数据。
4. 游戏音频辨别和训练反馈继续使用本地 M4A，不引入播放前网络依赖。
5. 动作说明语音改用稳定 CDN URL；语音仍是增强能力，加载失败继续以文字说明降级且不阻塞训练。
6. 资源发布可验证、可回滚；旧版小程序引用的资源不得被覆盖或删除。
7. 不占用录像流程需要的持久化文件空间，不改变现有 `saveFile` 清理铁律。

## 3. 已确认决策

1. 保留现有 `pages/game-session` 普通分包和点击时加载流程。
2. 将现有 18 张游戏图片和 5 段动作说明语音迁移到公开 HTTPS CDN；37 段游戏音频继续留在游戏分包。
3. 不继续拆首页、处方、运动训练等普通页面；当前主包体积健康，额外分包收益不足。
4. 不把固定游戏图片或动作说明语音 URL 写入数据库、动作库或处方快照。这些素材属于随代码
   版本发布的产品资源，由前端资源清单管理。
5. CDN 地址使用稳定公开 URL，不使用会过期的临时签名 URL。资源不包含患者数据，可公开读取。
6. 图片使用内容哈希文件名和长期不可变缓存；发布新图片时生成新 URL，不覆盖同名旧对象。
7. 游戏页使用 `Taro.getImageInfo` 在当前会话预取所需图片，并使用返回的临时路径完成本次游戏；
   本期不调用 `Taro.saveFile`，不建立持久化图片缓存。
8. 图片型游戏只有在本次需要的全部图片准备成功后才能开始。加载失败时提供重试和返回处方，
   不用文字占位继续正式训练。
9. 图片优先生成 WebP 版本；如目标 iOS 或 Android 真机存在兼容或画质问题，可退回优化 PNG，
   不改变资源清单和发布结构。
10. 动作说明播放器直接使用清单解析出的稳定 HTTPS M4A URL；保留现有自动播放一次、手动重播、
    90 秒超时、停止、销毁和文字降级行为，不把语音下载设为训练前置条件。
11. 删除两对未使用的肩部推举重复提示音源文件，并为生产构建增加软预算和微信平台硬上限检查。
12. 本期不启用 Taro `mini.optimizeMainPackage`，不迁移游戏音频，不建设后台素材管理系统。

## 4. 方案边界

### 4.1 包含

- 18 张游戏图片和 5 段动作说明语音的源文件目录、外部产物、版本化资源清单和 CDN 发布规则。
- 小程序构建环境中的游戏资源基础 URL。
- 游戏页图片预取、进度、失败、重试、页面卸载失效和临时路径解析。
- 删除游戏图片的 Taro 本地复制规则，确保 PNG 不再进入分包。
- 删除未使用的重复网络提示音源文件。
- 生产包体检查脚本和发布验收。

### 4.2 不包含

- 游戏音频、网络告警音频或运动视频迁移。
- 私有对象存储、签名 URL、鉴权、防盗链或图片管理后台。
- 离线可用的持久化图片缓存。
- 后端模型、API、migration 或训练记录结构变更。
- 游戏玩法、计分、难度、逐题明细和补传语义变更。
- 进一步拆分六款游戏页面或修改分包边界。

## 5. 静态资源结构

### 5.1 仓库源文件

原始 PNG 和已验收 M4A 需要保留用于重新生成和回滚，但必须移出 Taro `sourceRoot`，避免被误打包。
建议目录：

```text
miniapp/resources/game-images/source/
  pattern_*.png
  category_*.png
  sound_*.png
  puzzle_*.png
miniapp/resources/motion-instruction-audio/source/
  motion-*.m4a
```

构建后的外部发布产物写入被 Git 忽略的目录：

```text
miniapp/output/static-assets/<asset-version>/
  manifest.json
  <game-image-key>.<content-hash>.webp
  <motion-source-key>.<content-hash>.m4a
```

`asset-version` 用于发布批次识别，文件名中的内容哈希才是缓存失效和不可变性的最终依据。

### 5.2 图片规格

- 图案、分类和声音卡图片：输出 256×256 WebP，质量参数 Q85，不保留元数据。
- 拼图图片：保持 384×384 WebP，质量参数 Q85，不降低拼图切片所需分辨率。
- 不改变宽高比，不在图片内增加文字，不裁掉主要识别对象。
- 转换必须由可复现脚本完成，不依赖开发者手工逐张导出。

当前素材试算结果：原始 PNG 合计约 882.6 KiB；按上述规则生成的 WebP 合计约 298.1 KiB。
该数字是 CDN 首次下载体积参考，不计入小程序代码包。

动作说明语音保持当前已经验收的 AAC 单声道 M4A 内容，不重新转码，发布脚本只计算哈希并复制为
不可变文件名。5 段 M4A 合计约 1,028.4 KiB，从主包移除后由播放器按需读取。

### 5.3 CDN 对象路径

建议复用现有稳定静态资源域名能力，例如：

```text
https://<assets-domain>/motioncare/static-assets/<asset-version>/<hashed-file>
```

CDN/对象存储要求：

- HTTPS 证书有效，域名加入微信小程序合法业务域名。
- 图片返回 `Content-Type: image/webp`；使用 PNG 兜底时返回正确 PNG 类型；M4A 返回
  `Content-Type: audio/mp4` 或经目标微信真机验证可播放的等价正确类型。
- `Cache-Control: public, max-age=31536000, immutable`。
- 已发布对象禁止同 key 覆盖，旧 `asset-version` 至少保留到所有引用它的小程序版本停止使用。
- 发布环境不得把对象存储密钥、上传 token 或管理 API 密钥写入小程序代码。

## 6. 前端资源清单与构建配置

### 6.1 资源清单

生成脚本输出一份带资源类型的版本化清单。游戏分包内使用类型安全的图片 key，运动训练公共模块
使用现有正式动作 `source_key` 作为语音 key：

```ts
type GameImageKey =
  | 'pattern_sun'
  | 'pattern_coconut'
  | 'pattern_boat'
  | 'pattern_lighthouse'
  | 'pattern_shell'
  | 'category_pineapple'
  | 'category_bird'
  | 'category_train'
  | 'category_drum'
  | 'category_phone'
  | 'sound_bird'
  | 'sound_train'
  | 'sound_phone'
  | 'sound_laugh'
  | 'sound_drum'
  | 'puzzle_beach'
  | 'puzzle_garden'
  | 'puzzle_lighthouse'

type MotionInstructionAudioKey = MotionSourceKey
```

构建产物 `manifest.json` 记录资源类型、业务 key、内容哈希文件名、媒体类型、字节数和 SHA-256；
图片额外记录宽高。小程序中的 TypeScript 清单由同一脚本生成或校验，不能维护第二份容易漂移的
手写 URL 表。

玩法模块继续只关心业务 key，不直接拼 CDN 路径。资源解析模块负责：

```text
资源类型 + 业务 key
  -> 构建期资源清单
  -> TARO_APP_ASSET_BASE_URL + 版本化相对路径
  -> 图片：当前游戏页面会话的临时本地路径
  -> 动作语音：稳定 HTTPS M4A URL
```

### 6.2 环境变量

新增 `TARO_APP_ASSET_BASE_URL`：

- 正式微信小程序构建必须是绝对 HTTPS URL，否则构建失败。
- development/test 可以显式配置测试 CDN；测试中可注入假地址。
- URL 末尾斜杠由统一解析函数规范化，玩法代码不得自行处理。
- 不在仓库提交环境专属密钥；基础 URL 本身是公开配置，可以写入部署环境示例。

### 6.3 Taro 打包调整

- 删除 `config/index.ts` 中复制游戏图片目录到 `dist` 的 `copy.patterns` 项。
- 删除 `instructionAudioManifest.ts` 中 5 个本地 M4A 静态导入，改为解析外部资源清单 URL。
- 游戏音频两个复制项保持不变。
- `project.config.json` 的 `setting.minified` 调整为 `true`，作为开发者工具上传保护。
- 正式发布仍必须执行 `build:weapp:prod`，不能依赖开发者工具临时压缩替代生产构建。

迁移完成后，`dist/pages/game-session/assets/images/` 不应存在任何游戏 PNG、WebP 或其它图片，
`dist/features/motion-training/assets/audio/instructions/` 不应存在任何动作说明 M4A。

## 7. 游戏图片准备流程

### 7.1 每款游戏所需资源

- 颜色顺序、数字抑制：无远程图片，可直接进入现有准备流程。
- 图案顺序：预取 5 张 `pattern_*`。
- 分类切换：预取 5 张 `category_*`。
- 声音辨别：预取 5 张 `sound_*`；音频仍从本地分包播放。
- 视听拼图：预取 3 张 `puzzle_*`，避免下一轮随机选图时才临时等待。

图片映射必须按当前 `gameCode` 静态确定，不能下载其它游戏的无关图片。

### 7.2 状态机

图片型游戏在现有介绍/准备阶段增加：

```text
idle
  -> loading（显示已完成数量/总数和百分比）
  -> ready（启用开始按钮）
  -> failed（显示失败提示、重试、返回处方）
```

加载器最多同时请求 3 张图片，避免一次并发 18 个请求。每个 key 调用 `Taro.getImageInfo`：

- 成功：保存本页面会话内的 `key -> tempFilePath`，渲染统一使用临时路径。
- 失败：本轮整体进入 `failed`，销毁已完成映射；重试时重新建立一轮加载上下文。
- 页面卸载、切换动作或开始新一轮加载：旧回调失效，不能覆盖新页面或新轮次状态。

本期不调用 `saveFile`。临时路径只服务当前页面会话，页面退出后不承担冷启动恢复职责；跨会话
复用由微信网络缓存和 CDN 长缓存负责。

### 7.3 失败语义

视觉图片属于正式训练刺激，缺失图片会改变任务难度和结果可比性。因此：

- 图片未准备完成时禁用“开始训练”。
- 加载失败显示“训练图片加载失败，请检查网络后重试”。
- 提供“重新加载”和“返回当前运动计划”。
- 不创建训练开始状态，不启动计时，不写逐题记录，不上传失败训练记录。
- 非图片游戏和当前已加载完成的其它功能不受 CDN 故障影响。

## 8. 动作说明语音 CDN 读取

`instructionAudioManifest.ts` 继续提供 `getMotionInstructionAudioSrc(sourceKey)`，调用方接口不变；
内部从构建期静态资源清单解析稳定 HTTPS M4A URL，不再静态导入本地文件。

动作说明页继续遵守已验收行为：

- 正式动作加载完成后自动播放一次。
- 播放中禁用重播，播放结束后允许重新播放。
- 进入预览、开始训练、页面隐藏或卸载时停止并销毁音频上下文。
- 网络错误、播放错误或 90 秒超时显示“语音播放失败，请阅读文字说明”，但不阻塞文字、预览或训练。
- 未知和非正式 `source_key` 不生成 URL、不显示播放按钮，也不发起网络请求。

动作语音不使用 `getImageInfo`、`downloadFile` 或 `saveFile`。播放器把稳定 HTTPS URL 直接赋给
`InnerAudioContext.src`，微信/CDN 自行处理网络缓存。页面现有的播放代次隔离必须继续阻止迟到
回调覆盖新动作或已离开的页面。

本节局部覆盖 `2026-09-01-motion-instruction-voice-design.md` 中“5 段 M4A 本地内置”的决策；
预生成模型、声音版本、自动播放、重播、生命周期、文字降级和不修改后端的其它决策保持不变。

## 9. 重复音频源文件清理

`network_slow_paused.m4a` 和 `upload_recovered.m4a` 只保留一份公共二进制资源。肩部推举和公共
运动训练告警模块都引用同一资源路径，现有播放、超时、静音、页面生命周期和失败降级保持不变。

当前生产构建已经只打入公共目录的一份音频，因此该调整只清理未使用源文件，不计入包体节省，
也不合并两个业务流程的状态机或修改游戏音频。

## 10. 包体预算

新增生产构建后的只读检查脚本，按生成的 `dist/app.json` 解析主包和所有 `subPackages.root`，
计算真实文件字节数，不使用 `du` 的磁盘块大小。

检查分两层：

| 规则 | 阈值 | 处理 |
| --- | ---: | --- |
| 主包项目预算 | 1.2 MiB | 超过则构建失败 |
| 任一分包项目预算 | 1.5 MiB | 超过则构建失败 |
| 主包/单分包平台上限 | 2 MiB | 超过则构建失败并明确指出包名 |
| 全部代码包平台上限 | 20 MiB | 超过则构建失败 |

脚本输出主包、每个分包、总包及最大的若干文件，方便发现素材回流。额外断言游戏图片目录没有
进入 `dist`。

Taro `mini.optimizeMainPackage` 本期保持关闭。将来只有主包接近项目预算，并经过依赖分析证明
公共 chunk 是主要来源时，才单独评估开启；不能为了降低主包而无条件复制模块到多个分包。

## 11. 发布与回滚

发布顺序固定为：

1. 从仓库源 PNG 生成版本化 WebP，并给 5 段已验收 M4A 生成内容哈希文件名和统一资源清单。
2. 校验 23 个业务 key 唯一、文件存在、媒体类型、SHA-256 和字节数；图片额外校验尺寸。
3. 上传全量新版本目录到 CDN/对象存储。
4. 对每个正式 URL 执行 HTTPS、状态码、媒体类型、缓存头和可读取性探测。
5. 使用同一资源版本构建正式微信小程序。
6. 执行包体检查、自动化测试和微信开发者工具包体分析。
7. 在 iOS、Android 真机完成图片游戏加载和重试验收后上传体验版/正式版。

任何资源探测失败都不能继续上传引用该版本的小程序。回滚只需重新发布引用旧 manifest 的小程序
代码；旧 CDN 对象不得删除或覆盖。

## 12. 测试与验收

### 12.1 自动化测试

- 18 个业务 key 均有且只有一个资源清单项，清单文件名包含内容哈希。
- 5 个正式动作 `source_key` 均有且只有一个 M4A 清单项；未知动作不解析 URL。
- production 微信构建拒绝空值、相对 URL 和非 HTTPS 资源基础 URL。
- URL 拼接正确处理末尾斜杠，不产生双斜杠或遗漏版本目录。
- 每款游戏只返回自己的图片 key 集合，两个无图片游戏返回空集合。
- 预取成功后返回完整临时路径映射；部分失败不得返回半套可用映射。
- 并发不超过 3，重试会生成新轮次，旧回调不能覆盖新轮次结果。
- 页面卸载或切换动作后迟到回调不更新状态。
- 图片未 ready 时不能开始游戏；失败可重试或返回处方。
- 动作语音返回稳定 HTTPS URL；自动播放、重播、失败文字降级和页面生命周期测试继续通过。
- 现有游戏判分、计时、暂停、逐题数据、上传和补传测试继续通过。
- 两个运动流程继续播放同一语义的网络提示音，未使用重复源文件被删除，构建产物仍只包含一份。
- 包体检查覆盖主包、单分包、总包、软预算及游戏图片误入包体。

## 13. 风险与控制

- **CDN 故障阻断图片游戏**：这是保持训练刺激一致性的有意选择；提供重试和返回，不提交缺图数据。
- **CDN 故障导致动作语音不可用**：动作语音是增强能力，保留文字并允许继续预览和训练。
- **WebP 兼容或画质问题**：发布前双端真机验收；必要时同结构切换为优化 PNG。
- **旧资源被清理导致旧版失效**：对象不可变且旧版本长期保留；回滚不依赖重新上传同名文件。
- **环境配置错误**：production 构建强制 HTTPS，并在上传小程序前逐 URL 探测。
- **固定素材重新进入代码包**：源文件移出 `sourceRoot`、删除静态导入和复制规则，并由包体脚本断言。
- **持久化空间与录像冲突**：本期禁止 `saveFile`，不改变现有录像文件清理范围。
- **主包公共依赖膨胀**：资源清单和预取模块保留在游戏分包，不从主包导入游戏实现。

## 14. 完成标准

   5 段动作说明 M4A。

3. 游戏音频继续本地播放；动作说明语音改为 CDN 后仍保持自动播放、重播和非阻塞文字降级。

5. 不新增 `saveFile` 使用，不影响肩部推举录像空间预检和清理。
