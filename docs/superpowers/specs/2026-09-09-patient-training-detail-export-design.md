# 单患者训练明细导出

修订（2026-09-09, Codex）：用户已确认顺序题每步选择数据及未完成步骤保留，拼图新增点击次数；新设计 `2026-09-09-game-selection-detail-design.md` 覆盖本文件中五表结构、仅整题采集及未判定题丢弃条款。其他授权、健康窗口、安全和历史有效耗时规则继续适用。

## 1. 已确认需求与当前事实

用户确认：

- 首版只支持单个患者，选择该患者的一个项目和日期范围。
- 使用 Excel，包含训练场次、游戏逐题、运动明细、训练期间生理数据和字段说明五个工作表。
- “点击耗时”沿用此前约定的逐题有效作答时间，不采集每一次普通点击。
- 导出运动情况及训练期间心率、血压、血氧原始读数和每场摘要。
- 一次补齐规范逐题采集与导出；逐题明细仅展示可确认的有效作答耗时，缺失值不填 0。旧原始数据在后台保留，不作为有效耗时导出。

当前代码事实：

- 后台有训练追踪与运动结果查看，没有训练明细 Excel 导出接口和入口。
- 2026-08-21 的逐题设计已批准，其计划仍为 review；当前代码尚无 GameQuestionResult 和游戏客户端会话幂等字段。
- 游戏当前以 raw_detail.rounds 保存逐轮信息；response_ms 直接用 Date.now() 相减，不保证排除暂停等时间。
- 运动结果已经归集到 TrainingRecord；视频会话保存首次开始、可空实际结束、实际秒数与处方时长快照。
- WearableMeasurement 已保存患者归属、采集时间和三类生理指标，能够按现有健康观察窗口查询。

本设计扩展 2026-08-21 设计中“不新增逐题数据导出”的边界。其采集、幂等、旧数据兼容规则继续适用；本轮只承接导出必需的数据基础，不自动实施该旧计划里的完整趋势图和逐题抽屉。旧 spec/plan 保留，不能误标为全部实施。

## 2. 用户流程

患者“训练与健康”详情页顶部增加“导出训练明细”。打开轻量弹窗：

1. 显示当前患者；项目默认使用详情页当前选中关系，可切换该患者有权限的其他项目。
2. 时间范围提供近 7 天、近 30 天、自定义、全部历史；默认近 30 天。
3. 自定义使用日期范围，含开始日和结束日；按训练日期筛选场次，不按上传时间筛选。
4. 说明导出包括游戏、运动和生理明细，以及历史数据可能缺失。
5. 点击“导出 Excel”后显示生成中，阻止重复点击；成功触发下载，失败保留筛选条件并提示重试。

项目状态不在弹窗或文件中外显；已完结项目仍可只读导出。无可访问项目时禁用入口并说明原因。导出不会只取页面中的最近若干条记录或当前处方，而是读取选定项目关系和日期范围内全部历史处方版本的训练记录。

单患者跨项目不混合输出；不新增整项目批量导出入口。动作分析仍在进行的场次可以导出，结果状态和缺失原因明确保留；导出不会触发或等待 AI 分析。

## 3. 工作簿结构与公共规则

文件名：患者编号_项目编号_训练明细_日期范围_导出时间.xlsx。患者姓名放在表内，不放在文件名；手机号沿用脱敏形式。时间统一为 Asia/Shanghai，列名带单位，数值保存为 Excel 数值类型，日期时间格式为 yyyy-mm-dd hh:mm:ss。

所有明细通过“训练记录编号”关联；患者编号、项目编号、项目患者编号用于明确身份和分组边界。分组名称使用导出时当前绑定值，并在说明中标明不是训练时历史分组快照；动作名称和处方参数使用训练记录关联的处方快照。

缺失数值留空，另用数据可用性/原因列解释。真实 0 和 false 必须保留，不能被当成缺失。不得使用上传时间代替训练时间、整数分钟反推精确毫秒、计划次数代替实际次数。

### 3.1 训练场次：一条训练记录一行

字段：

- 患者编号、姓名、脱敏手机号；项目编号、名称；项目患者编号、分组名称。
- 训练记录编号、训练日期、训练记录提交时间；处方编号、版本、处方动作编号、动作编码、动作名称、训练类型。
- 训练完成状态、计划时长（秒）、实际训练时长（秒）、时长来源/精度。
- 训练开始时间、实际结束时间、起止时间可用性。
- 游戏得分、实际难度、处方难度、是否调整难度、完成题数、正确题数、错误题数、正确率、是否提前结束、结束方式。
- 逐题记录数、规范计时题数、逐题数据完整性；备注。题数反映实际导出的有效逐题行，不展示历史计时题数。
- 生理观察窗口开始/结束、窗口口径、心率/血压/血氧数据可用性；三类读数数量及摘要。

游戏时长优先取 raw_detail.session_duration_seconds；旧普通训练若只有 actual_duration_minutes，则换算为秒并标为“按分钟记录”，不声称精确到秒。运动实际时长优先取视频 actual_duration_seconds，视频文件时长单独放在运动表，不混为同一指标。

旧及当前游戏没有可靠绝对起止时间时，相应单元格留空。本轮不为导出新增游戏绝对时间或独立游戏生理观察窗口；游戏有效时长照常可导出。该限制在导出弹窗和说明表中可见。

游戏摘要仅在正式题目全部有效、题号从1连续递增且题数与场次保存的规范完成题数一致时使用逐题权威汇总；缺题、过滤或无法确认完整性时保留原摘要并明确说明；旧场次摘要保留原值，并标明题目条数可能与摘要不完全一致。拼图的正确率列留空，说明“不适用”；不会以完成即正确计入综合正确率。

### 3.2 游戏逐题：每道已完成或已判超时题一行

字段：训练记录编号、训练日期、游戏编码/名称、题号、实际难度、有效作答时间（毫秒）、判定（正确/错误/超时）、实际交换次数、采集版本、数据口径说明。

- 仅导出 active_response_v1 且有效耗时为 0 至 3,600,000 毫秒整数的题目；真实 0 保留。legacy_wall_clock_v0 和缺失有效耗时的题目不进入逐题明细，删除历史耗时列。
- 正常采集的正确、错误、超时判定均保留；无效数据指无法确认有效耗时的数据，不是答错。
- 颜色/图案顺序以完成整段复现为一题；反应抑制、分类转换和声音辨别以一次最终判定为一题；拼图以完成一幅为一题。
- 拼图耗时就是该题完成耗时，实际交换次数为完成过程中发生的交换，不是点击次数。
- 整场结束时尚未完成、尚未判超时的当前题丢弃，不补造一行。
- 暂停、页面隐藏、序列/拼图展示、声音预览、说明语音和答后反馈不计入新版有效作答时间。
- 无逐题数据的游戏场次仍存在于“训练场次”；逐题表不插入虚构题目行。

### 3.3 运动明细：每场运动记录一行

字段：训练记录编号、训练日期、动作编码/名称、处方时长、首次录像开始、实际结束、实际训练秒数、视频文件秒数、动作总次数、标准次数、非标准次数、结果来源、结果更新时间、修订医生编号/姓名、分析状态、分析失败说明、动作质量详情、录像编号、录像处理状态、备注。

- 次数与质量读取 TrainingRecord 当前有效结果，不从“最后一个成功任务”重新计算；允许医生修订结果为最终来源。
- 动作质量详情保留可用质量字段和医生说明，使用稳定 JSON 文本；超过 Excel 单元格 32767 字符时分为“动作质量详情 1…N”连续列，说明按列顺序拼接还原，不静默截断。
- 无分析、不支持 AI、分析失败均不以 0 次表示。是否有结果与是否支持算法分别判断；不支持 AI 的动作仍可存在医生录入结果。
- 椰林步道模拟不支持 AI 监督；普通跟练、录像和医生录入结果仍可导出。
- 不打包患者视频或骨架视频，不在文件中写入七牛签名 URL、对象密钥或内部存储路径。

### 3.4 训练期间生理数据：一条“训练场次—测量记录”关联一行

字段：训练记录编号、录像编号、测量记录编号、测量时间、指标类型、心率（次/分）、收缩压/舒张压（mmHg）、血氧（%）、窗口开始/结束、窗口口径。

沿用已批准并实施的固定健康观察窗口：

window_start = TrainingVideo.training_started_at
window_end = window_start + expected_duration_seconds + 300 秒

- 这是“训练健康观察窗口”，不保证等同于实际训练起止区间；在表头说明和字段说明中明确“包含处方时长后 5 分钟”。
- 查询边界为闭区间，按 measured_at 筛选；实际结束、暂停、上传时间不改变窗口。
- 仅取归属于该患者且 attribution_status=attributed 的有效读数；绑定区间外和归属不明确的记录不纳入。
- 同一测量落入多个场次的重叠窗口时，可分别关联这些场次；保留测量编号，使用者可按编号去重，不能把重复关联当成新的测量。
- 心率、血压、血氧各自成行；不把不同采集时刻强行拼成一组，不插值、不补零、不用日平均替代时段读数。
- 心率/血氧各自输出数量、平均、最小、最大；血压分别输出收缩压/舒张压的平均、最小、最大及有效配对数量。摘要从同一批导出读数计算，均值保留一位小数。
- 没有可靠首次开始时间或处方秒数的运动场次、生理数据为空的窗口，明细不造数据；场次表分别标注“无可用观察窗口”或“窗口内无有效测量”。
- 当前游戏没有上述录像会话窗口，生理数据标为“无可用观察窗口”。本期不采集游戏绝对起止时间、不将整天读数冒充游戏期间数据。
- 不修改现有健康图表及厂商采集/同步方式。

### 3.5 字段说明

包含：导出人、生成时间、患者/项目、请求与实际数据日期范围、各表行数、格式版本 training_detail_v1、时区、字段定义与单位、关联规则、三类时长区别、计时版本、缺失含义、拼图口径、窗口算法、重叠测量去重规则和数据读取截至点。

表格冻结首行、自动筛选、统一日期/小数格式，长说明换行；明细区不合并单元格。空数据仍输出五个表和说明，给出 0 行而不是错误或空文件。

## 4. 数据基础：承接已批准的逐题采集设计

新增 GameQuestionResult 及 TrainingRecord 的 client_session_id、client_payload_fingerprint，复用 2026-08-21 设计的字段约束：

- 题号从 1 连续递增，单场最多 2000 题，单题有效时间不超过 3600000 毫秒；时长和交换次数非负。
- 游戏编码匹配处方动作；actual difficulty 接受简单/中等/困难任一档，可高于或低于处方默认值；新记录调整原因为空。
- timeout 必须为错误；新版拼图完成题必须为正确且有交换次数，非拼图不提交交换次数。
- 逐题有效时长总和不得超过整场秒数×1000＋1000 毫秒。
- 新版六游戏共用可暂停的单调计时器；正常结束和提前结束均只批量上传已判定题目。
- 后端在事务中写入场次与全部题目；逐题非法时整体回滚。
- 新版游戏生成会话 UUID，直接上传和补传保持同一值；重传匹配返回原记录，内容冲突返回 409，不覆盖原记录。
- 语义指纹排除后端派生汇总及 upload_mode/retry_count/total_retry_count，不能因补传元数据变化制造冲突。
- 幂等检查先在患者与原处方动作范围内定位并校验已有记录，使成功后处方切换的合法重传仍返回原记录；首次创建继续执行当前生效处方检查。不能因 UUID 已存在而泄露其他患者记录。
- 现有媒体生命周期、2 秒序列展示、六游戏 Excel 难度规则、无反馈自由调难、签名素材和普通运动录像均保持不变。

本期不自动增加长期统计图、全新分析页面或每次普通点击事件流；导出基础对未来逐题查询可复用。

## 5. 历史数据与上线兼容

导出仅使用正式 GameQuestionResult 中合法的 active_response_v1 题目，不展开旧 raw_detail.rounds，也不导出迁移产生的 legacy_wall_clock_v0 题目。以下历史存储与写入兼容行为继续保留。

- 首次迁移按既有逐题设计扫描可识别旧 rounds，合法项转为 legacy_wall_clock_v0；异常项跳过，原始 JSON 不改写或删除。
- 历史题目若序号不连续，保留来源题号；新版连续题号规则只作用于新版写入。重复题号、非法时间、非布尔正确性不生成伪造题。
- 后端上线后、客户端更新前的旧 payload 仍可接收，并即时解析合法旧 rounds；旧客户端没有 UUID 时保持原有兼容行为。
- 迁移与旧写入兼容解析使用一致的冻结规则与测试样例。记录扫描、创建、跳过数量用于验收，不在日志输出患者原始数据。
- 导出不展示旧墙钟耗时及其说明；无法还原有效耗时的旧场次仅保留其已有合法整场汇总，逐题记录数为实际导出行数，并标注有效逐题记录不可用，不伪装成完整列表。
- 历史快照、有效训练记录和用户已经修订的运动结果均不被导出过程改写。

## 6. 导出接口与权限

新增：POST /api/training/tracking/patients/{patient_id}/export/

请求：project_patient 为必填；range 为 7d/30d/custom/all，custom 同时传 start_date 和 end_date。非 custom 传自定义日期、非法日期、反向范围、结束日期晚于上海当天均返回明确的 400，不静默更正。all 的范围由真实训练记录决定。

响应：200，标准 xlsx MIME、Content-Disposition 附件文件名，Cache-Control: no-store。空结果仍返回可打开的带表头工作簿。失败为标准 JSON 错误，前端按 Content-Type 解析，不能把错误内容保存成 xlsx。

- Django Session＋CSRF，医生/管理员权限，复用 accessible_project_patients 的实际行级范围；项目患者必须属于 URL 中患者。
- 越权或不匹配统一 404；已完结项目允许读取，不能复用会阻断已完结项目的写操作门禁。
- 全部训练、视频、逐题数据由已授权记录集合向下查询；生理数据使用已授权患者和已授权场次窗口。
- 不以客户端传入任意训练记录、设备、对象键或下载地址作为授权依据。
- XLSX 使用显式文本单元格写入患者/项目/备注/JSON等字符串，防止 =、+、-、@ 开头内容被当作公式；不生成宏、外部链接或自动超链接。
- 新增轻量 TrainingDetailExportLog：导出人、患者/项目关系、筛选条件、生成起止时间、结果、格式版本、各表行数和脱敏错误分类；文件本身不长期存储。审计引用允许源实体删除后保留标识快照，不能反向阻止既有解绑删除流程。
- 审计“成功”表示文件已生成并开始返回，不声称用户已保存文件。

## 7. 性能与生成一致性

首版同步生成单个患者文件，不新增导出任务中心。后端使用 openpyxl 的 write-only 工作簿、数据库分批读取和权限私有的临时文件，生成完成后返回文件流，关闭响应时清理临时文件；异常路径也清理。

- 生成时使用一致的数据库读取快照，文件各表与摘要在同一读取截至点上保持一致；审计写入独立处理，不把日志写入只读事务。
- 按训练日期、训练记录编号、题号或采集时间稳定排序；避免一场一次 SQL 的逐题/测量 N+1 查询。
- 首版每次最多 10000 场训练，各数据表最多 200000 行，整个文件最多 500000 条数据行。写入过程中也检查行数，超限终止并提示缩小日期范围，不能截断后返回成功。
- 每次生成最长 60 秒；数据库语句超时和生成截止均有保护，失败清理临时文件并提示缩小范围。实施时配套核对代理/应用请求超时足以返回明确错误。
- 长文本按 Excel 单元格限制拆分，非法 XML 控制字符安全替换并在说明表记录处理数量；数值和单位不改变。
- all 表示不按日期过滤，不承诺突破上述容量限制；这些限制在弹窗帮助文字中说明。

## 8. 验收

### 数据采集

六款游戏分别验证展示/可作答/暂停/隐藏/恢复/语音/反馈/超时/主动结束；时间正确排除非作答阶段。拼图仅实际交换计数。UUID 补传不变、内容冲突拒绝、当前处方切换后已成功会话可幂等返回；新创建仍拒绝过时处方。

### 导出内容

- 使用含两项目、历史处方、六游戏、不同难度、AI/医生运动结果及三类测量的已知样本，逐单元格核对关键结果。
- 验证记录跨午夜、日期首尾、上海时区、同日多场、空文件、缺失和真实 0。
- 逐题表只含可用的有效作答耗时与判定；历史耗时列、历史计时题数及旧口径说明均不导出；旧数据不伪造，拼图不计算正确率。
- 健康窗口严格为首次录像开始＋处方秒数＋300；更换当前处方、实际结束缺失/变化不影响窗口。
- 同一测量跨窗口可追溯；不同患者、归属不明读数不进入文件；摘要与明细一致。
- 行数超限、长字段拆分、控制字符、公式文本、生成失败和临时文件清理。

### 权限与界面

医生/管理员可访问范围与详情页一致；其他角色、未登录、跨患者、跨项目篡改均拒绝。已完结项目能导出且文件不展示项目状态。弹窗默认项目/范围、日期校验、生成中、重复点击、错误 JSON、文件名、空结果和项目切换均有验证。

使用 Excel 兼容读取器打开实际生成的文件，并渲染或实机打开样本核对列宽、换行、冻结、筛选和日期格式，不能仅验证返回字节数。
