# 微信小程序中性术语设计

## 目标

仅在 `miniapp/` 中把用户可见的医疗相关词语机械替换为中性的运动表达，使页面、按钮、提示、错误信息和小程序项目描述不再使用患者、医生、处方、康复等医疗措辞。

Web 管理端、后端接口、数据库和既有领域模型不在本次范围内。

## 固定替换表

| 原词 | 固定替换词 |
| --- | --- |
| 患者、病人 | 用户 |
| 医生、医护 | 指导老师 |
| 处方 | 运动计划 |
| 康复 | 运动 |
| 医疗 | 运动服务 |
| 诊疗 | 运动指导 |
| 医嘱 | 运动说明 |
| 治疗 | 训练 |
| 医院 | 服务机构 |
| 疾病 | 身体情况 |

替换采用机械规则，不对替换后的句子做额外润色；允许出现“运动计划建议时长”等表达。

## 修改范围

必须覆盖以下微信小程序展示区域：

- `miniapp/project.config.json` 的项目描述。
- 首页、绑定页和运动计划页。
- 游戏训练、动作历史页面。
- 肩部推举介绍、预览、录像和上传页面。
- 页面按钮、标题、加载态、空状态、错误提示和由小程序生成的训练备注。
- 对应用户可见文案的测试断言。

以下内容必须保持不变：

- `frontend/` Web 管理端和 `backend/` 后端。
- API 字段、请求路径、数据库字段、TypeScript 类型与内部英文变量，例如 `patient`、`doctor`、`prescription`。
- 用户输入、姓名、项目名称、动作名称及接口正常业务数据。
- 测试名称和仅用于描述内部接口语义的测试数据；只有用户可见断言需要同步修改。

## 接口错误展示

新增一个小程序专用的术语转换函数，按固定替换表对错误提示文本做全量字符串替换。该函数只在错误展示边界调用，不处理正常接口数据。

页面中的固定错误文案直接机械替换；接口返回的 `detail`、`message` 或 `Error.message` 在写入界面错误状态前经过同一转换函数。未知错误继续使用各页面现有的兜底文案。

## 验证

- 为全部固定替换规则增加单元测试，并验证中性文本保持不变。
- 更新首页、绑定、运动计划、游戏训练、动作历史和肩部推举相关页面测试中的可见文案断言。
- 静态扫描 `miniapp/src` 的非测试生产展示文件与 `miniapp/project.config.json`；除集中声明固定映射的术语转换器外，不得残留固定替换表中的原词。
- 运行小程序全量测试、开发微信构建和生产微信构建。
- 构建产物继续使用新的微信 AppID，并连接 `https://mcare-wx.whestsun.com/api`。

## 开发版发布

- 复审通过后提交并推送 `main`。
- 上传微信开发版版本 `2026.08.11.2`。
- 开发版描述固定为 `性能优化`。
- 不使用或保存 AppSecret。
- 只有测试、双构建和微信开发者工具 CLI 上传均成功，才能报告开发版已上传；微信后台版本列表仍由平台侧确认。
