## 1. 用户目标与验收口径

医生或研究人员应能方便地填完原 Word 中每个适用的填写位置。每个输入必须有明确的提交字段，保存后能重新打开核对，并出现在对应的 CRF 预览及导出位置。满意度、未完成原因、研究者处理、不良事件处理与转归、退出原因、各项备注均属于研究数据。

“字段完整”须以原表逐格核对，不能用 registry 条目数量或测试通过数量替代。现有源表为 31 张表、265 行；按选择组、空白填写位、日期及原纸面重复行分别计数，核查清单有 561 个语义填写位置。可重复组件可用一组列定义覆盖多行实例；同一受试者编号可复用同一数据源，仍必须覆盖所有出现位置。静态题干、操作提示和版本常量不生成患者回答。

每个填写位置的最终验收记录必须明确：原表位置 → 字段/组合字段 → UI 控件 → 提交路径 → 回读结果 → 预览位置 → DOCX 位置 → PDF 位置。任何位置没有接线、只藏在一段总备注里或导出未落格，均不能通过。

## 2. 已验证的修复依据

1. 线上后端、管理端和本地测试使用同一提交，348 个被比对的后端、协议包及模板文件哈希相同。

4. “完成”操作仅提交状态，会丢失未暂存的当前输入；访视日期没有有效录入及提交接线。

6. 数值校验缺少范围、整数和合计一致性约束；JSON 日期只做形状检查，非法日历日期可通过。

## 3. 沿用的业务边界

- `Patient` 继续为全局患者档案；`PatientBaseline` 保留现有标量字段和五段 JSON，只保留最新值。
- 访视仍使用 `VisitRecord.visit_date`、`form_data.assessments`、`form_data.crf`；`computed_assessments` 只由服务端写入。
- 保留草稿/已完成状态及项目归档的现有语义，不新增质控锁定流程。
- 遵守 PRD §10.2：缺失不阻止保存或完成；遵守 D028：允许带缺失预览和导出。完整性必须单独、准确展示。
- 纸面签名位置录入签名姓名/确认人及日期，不增加电子签名或签署法律效力。
- 不自动判断尚未提供的临床阈值或访视时间窗；相应选择、依据和原因由研究人员按批准方案录入。
- CRF 退出记录与解绑操作分开。填写退出记录不会自动解绑或删除访视；解绑仍遵守现有删除语义。退出记录须能在 T0/T1 提前退出时填写，并汇总到原表 #T29。
- CRF 不读取穿戴健康数据，遵守 D035。

## 4. 实现方式比较与建议

方案 A：全部按 registry 字段顺序渲染普通表单。维护成本低，字段、选项和规则容易保持一致，但量表、满意度矩阵和重复明细容易成为长串输入框。

方案 B（建议）：registry 统一描述字段、选项、规则、条件及导出位置；前端按临床章节分组，机能测量、量表矩阵和重复记录使用专用的章节布局，内部仍调用通用字段控件。数据规则只有一份，界面同时保留原表的上下文，适合本次“完整且方便填写”的目标。

采用方案 B。沿用现有患者基线/T0/T1/T2 入口；前后端通过同一 registry 合约工作。无需新建答案数据库模型或拆出独立量表系统。

## 6. Registry 与存储合约

继续以 `specs/patient-rehab-system/crf/registry.v1.json` 为受控真源，增加独立的 `schema_revision`；原 CRF 的 `template_revision` 仍为 `1.1`，两种版本不能混淆。前端副本由同步脚本生成并在 CI 中校验哈希一致。

字段定义保留稳定的 `field_id`、标签及现有可复用的 `storage`，补充：

- `section`、顺序、单位及帮助说明。`ui_label` 可提供简短展示名；原 `label_zh` 和 `hint` 保留给映射/导出使用，录入控件不再把 hint 拼到标签后。
- 可选的选择项值/标签映射；现有枚举值保持兼容，显示文字对齐原表。
- 数值范围、整数要求、日期精度、最大文本长度。
- `visible_when`、`required_when`、是否纳入完整性；条件只支持受控操作，不执行任意表达式。
- 重复数组的列定义及子字段；前后端均递归处理。
- 明确的原表位置绑定，包含零起始的表/行/格、访视上下文及同格多个填写位的渲染顺序。原字段在 T0/T1/T2 的不同出现位置分别绑定，修正现有20处索引错误。
- 受控的数据状态及备注路径。渲染、校验、完整性和导出共同使用该定义。

患者基线五段 JSON 和访视 `assessments`/`crf` 继续承载业务值。新增键采用命名路径；不把布尔、数字或选择值拼成中文总描述。对已有字符串节点不得原地换成对象覆盖历史值，例如 `crf.completion` 保留为旧文本，新结构使用 `crf.completion_record`；`crf.qc` 与 `crf.qc_record` 同理。

基线的数据状态放在 `demographics._crf_field_meta`，访视状态放在 `crf._field_meta`，以受控完整存储路径为键。重复行有稳定 `_row_id`，每行保存自己的 `_field_meta`，删行或换顺序不会使原因错配到其他记录。

PATCH 合并规则：对象递归合并；未提交的键保持不变；显式 `null` 清除一个标量；数组作为整组替换，`[]` 可明确清空。基线也采用此规则，修复现有“局部提交整个 JSON 段被替换”的问题。服务端按合并后的候选数据校验，校验成功才落库。

`GET` 和 `PATCH` 继续保留现有响应字段；可增量返回 schema 版本、分章节完整性和字段错误信息。创建及更新走同一套校验，不能通过新建绕过规则。项目已归档等现有写保护覆盖所有写入口。

## 7. 不详、不适用与日期

输入值与“未知/不适用”分开：状态为 `value`、`unknown`、`not_applicable` 或未处理。用户通过小型状态选择控件切换；后两种状态显示原因输入。值字段保持正确类型；状态不能伪装成量表分数。

- `unknown` 或 `not_applicable` 需要说明才能被完整性统计视为已处理。允许先保存空说明的草稿，但列出缺少说明。
- 完整性展示同时列出正常已填、不详、不适用和未处理数量。“有不详”不能显示成“所有测量值已获得”。
- 旧数值 `88/99` 不能无条件转换成状态：某些测量值可能合法，超出量表范围的旧数据标记“需核对”。
- 选择题不默认选择“否”，计数和量表不默认填0，避免把未录数据变成真实观察。
- 精确日期使用 DatePicker；疾病确诊日期使用月份精度，存储 `YYYY-MM`，不虚构为每月1日。兼容读取旧 `YYYY-MM-DD`，保留原值直到用户确认修订。
- 原表允许未知日期部分；通过年/月/日分量控件和未知开关记录。已知部分必须有效，未知部分按原格式导出为 `99`，全未知年导出 `9999`。
- 模型 `visit_date` 仍只存真实完整日期或 `null`。部分访视日期存于受控 `crf.meta.visit_date_parts`；两种表示通过同一控件协调提交，不向 DateField 写入假日期，也不在缺少真实日期时计算访视周数。
- 仅凭形状匹配的 `2026-02-31`、`2026-13-99` 均不得作为真实日期通过。未知部分必须是明确的未知状态。

## 9. Ant Design 录入体验

- 是/否、能/不能、轻/中/重及1–5评分等短选项使用 `Radio.Group`；选项较多时使用可搜索 `Select`。
- 原表明确多选的药物类别、饮酒类别使用 `Checkbox.Group` 或多选 `Select`；题干未明确多选的项目保持单选。
- 数值用 `InputNumber`，展示单位、小数精度、上下限；量表小范围整数可用 Select。必填/缺失与非法值分别提示。
- 重复明细采用 Ant Design `Form.List`，支持添加、删除及字段错误定位；桌面显示明细表，较窄区域采用逐条分组布局。依赖使用完整的数组字段路径，避免行间串值。
- 每章节有填报进度及“查看未处理项”；字段显示简短名称、单位和实际选项。去掉常驻的长说明、来源表号、开发信息、原文记录提示及重复的章节介绍，不展示 registry/storage 等实现术语。
- 纳排标准等判断题保留决定答案的关键条件；数字边界以控件和必要错误提示表达。不能为了去掉说明而删掉数据输入、临床判定条件或选项文字。
- 只有相应答案触发时才显示“其他”、不能完成原因、药物明细等。保留已录的非活动子字段；完整性和导出依据父答案决定是否适用，避免误用隐藏旧值。
- 旧总文本单独展示为“旧记录，待核对”，不能自动填充新选择项，也不能据此将细项判为完整。
- 底部固定保存按钮及上次成功保存时间；请求期间禁用重复提交。服务端错误映射到具体字段并跳转，不只显示“保存失败”。
- 页面数据刷新不能覆盖正在编辑的草稿。切换章节保留表单值；离开存在未保存输入的页面应明确提示。

组件依据：[Ant Design Form 与 Form.List](https://ant.design/components/form/)、[Radio](https://ant.design/components/radio/)、[Select](https://ant.design/components/select/)、[InputNumber](https://ant.design/components/input-number/)。实施只使用仓库安装的 AntD v5 所支持的 API，不引入 v6 专用接口。

## 10. 保存、完成及数值核对

基线和访视提交都来自同一份当前表单值。清除值明确提交 `null`；日期、重复行及反馈备注不能被漏出提交体。

“标记完成”必须在一个 PATCH 内同时提交当前 `visit_date`、当前变更的 `form_data` 和 `status: completed`。服务端在一项数据库操作中保存，非法值时整次请求失败，不能出现状态已完成但值没保存。操作前列出未处理项，用户仍可按既有规则带缺失完成；完成状态与填报完整性分别显示。

前后端共用如下基础约束：

- 拒绝布尔冒充数字、非有限数、负数计数、小数计数、超出题目定义范围的选项/量表值。
- SPPB三项均为0–4整数，总分0–12；分项齐全时核对总分等于三项之和。缺分项时不补0、不伪造合计。
- MoCA分项满分依次5/3/6/3/2/5/6，教育修正0或1，总分0–30；分项及修正齐全时核对 `min(30, 分项和 + 修正)`。教育修正和≤22判定与已录资料矛盾时给出明确字段错误；资料缺失时提示待核对。
- 满意度每题和总体评分均为1–5整数；5题齐全时总分等于5题之和，范围5–25。
- 围度、耗时、握力、次数/时长有基本非负及有限值约束；不擅自设置未经方案确认的临床异常阈值。
- 比较最快步行时间、最大握力等可机械核对的派生值；提供“使用计算结果”操作，不在没有原始值时悄悄填值。
- 完成率和计数/时长拆开存储；0计划次数不做除法。原 CRF 未明确完成率应基于次数还是时长，保留研究人员输入，展示两个辅助比值而不强制选其中一个。超出0–100%的新值不能作为普通完成率提交。
- 当研究者记录“有事件/有变化/有手术/有过敏”时检查相应明细完整性；无明细仍可存草稿，但不会显示完整。未知/不适用按状态规则处理。

对历史非法或缺项值，读取时原样展示并标注“需核对”，不得自动改写。仅保存另一个章节不应因未修改的旧数据被拒绝；错误范围针对本次改动及受其影响的依赖规则。“完成”时仍完整展示尚存的历史问题。

## 11. 预览、缺失及 DOCX/PDF

聚合输出在现有身份信息、访视信息外增加按原表组织的 `sections`：每个字段的值、标签、适用性、未知状态、原因及重复记录。Web 预览展示所有细项；同一套数据供导出使用，避免预览与文件出现不同口径。

完整性由 registry 的条件规则逐项计算，区别：已填写、已注明不详/不适用、未填、选择后的说明未填、数据矛盾、旧记录待核对。可选普通备注不会强制要求每格编造内容，但必须可填、可保存、可导出。原表要求因不详/不适用作出的说明属于完整性检查项。11项摘要不能再代表全表完整。

DOCX 使用原模板，按受控位置回填原有格子和勾选项；保留题干、固定版本和操作说明。姓名缩写、年月精度、部分未知日期及88/99状态按原表规则表示。同格多个值使用显式字段组合渲染，不能依赖全文件同名或第一个下划线替换。

- T0/T1/T2 必须回填各自的表，重复受试者编号一致。
- 明细行超过原表容量时复制对应样式行并完整输出；无活动明细时保留适当空行，不输出隐藏旧记录。
- 普通缺失保持空白；明确未知/不适用显示99/88及原因。原因在已有备注位填写，无备注位时在对应行或受控补充说明中标明字段名，不能丢失。
- 提前退出以已录记录的最近访视上下文汇总到 #T29，发生冲突时提示核对，不默默取覆盖值。
- 旧总文本保存并在相应章节的历史补充说明中输出，不能冒充已经填写的新量表、勾选矩阵或事件明细。
- 导出日志记录实际使用的 CRF 模板版本，不能只记录与文件不符的项目配置版本。

PDF 从同一份已回填 DOCX 转换，不另写一套字段汇总。产品镜像需提供受控的转换程序及中文字体，设置超时并隔离转换工作目录。转换失败显式返回可理解错误，不能伪报成功并留下空的PDF地址。导出失败清理本次临时文件；完整导出日志与生成文件按成功结果关联。

导出与预览沿用已有角色和行级访问策略，检查目标项目患者权限，不因直接按主键查询绕过数据范围。
