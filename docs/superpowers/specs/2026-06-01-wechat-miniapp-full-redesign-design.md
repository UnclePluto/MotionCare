# 微信小程序整体重设计方案

## 背景

现有患者端小程序页面仍大量使用 `panel`、`field-card`、`row`、`primary-button` 等偏后台表单的结构和样式，视觉上接近 Ant Design 卡片与管理端表单。上一轮已将游戏页改向「海岛活力康复」，但首页、绑定、处方、健康填报、训练记录、历史页和游戏页仍缺少统一的患者端移动设计系统。

本设计参考 `nextlevelbuilder/ui-ux-pro-max-skill` 的移动端设计原则：移动优先、可访问、高对比、44px 以上触控目标、统一 token、明确 loading/error 状态、避免 AI 紫色渐变和后台卡片感。落地到微信小程序时不使用外部字体和 Web hover，优先使用微信系统字体、Taro/微信组件能力和小程序静态样式。

## 目标

- 全量重设患者端小程序的按钮、卡片、输入、提示、间距、字号、配色和信息层级。
- 保留小程序现有业务流、API、页面路径和游戏规则。
- 游戏页与非游戏页统一为同一套「活力康复湾」视觉系统。
- 游戏分包进入前主动动态加载，并展示可见进度条和失败提示。
- 保持游戏资源已拆入 `pages/game-session` 分包，避免回退到主包。

## 非目标

- 不改医生 Web 端设计。
- 不改后端接口、训练记录格式、补传机制或游戏判分算法。
- 不新增底部 TabBar、复杂成长系统、角色 IP 或运营活动。
- 不引入新的 UI 组件库、图标库或远程字体。

## 视觉系统

### 气质

名称：活力康复湾。

关键词：清爽、明亮、可靠、年轻、成人友好、有轻游戏感。

避免：后台灰底、纯白表单堆叠、Ant Design 蓝按钮、过重阴影、幼儿化卡通、紫粉 AI 渐变。

### 色彩

- 页面背景：浅青 `#E9FBFF`、薄荷绿 `#EAFBF0`、暖阳黄 `#FFF4D6`。
- 主色：海水青 `#0798B2`。
- 主行动：健康绿 `#11A36A`。
- 强调：珊瑚 `#FF6B5A`、阳光黄 `#FFB84D`。
- 正文：深海蓝绿 `#073B4C`。
- 次级文字：`#52727D`。
- 边框：`rgba(7, 59, 76, 0.12)`。
- 危险：`#C2412D`。

### 字体与间距

- 使用微信系统字体栈，不加载远程字体。
- 页面标题 38-44px，卡片标题 28-34px，正文 25-28px，辅助文本 22-24px。
- 页面左右安全间距 28px，模块垂直间距 18-28px。
- 点击目标最小高度 88px；紧凑按钮最小高度 72px。
- 字距保持默认，不使用负 letter-spacing。

### 组件

- 页面：柔和渐变背景，顶部有轻量 hero/标题区。
- 信息块：半透明暖白底，圆角 24px，弱边框和轻阴影；不再使用后台式硬边 Card。
- 按钮：胶囊形，大字号，高对比；主按钮绿青渐变，次按钮浅底深字，危险按钮珊瑚浅底。
- 输入：大圆角、浅底、强焦点感；绑定码格更像移动端验证控件。
- 进度：使用暖阳/健康绿进度条，明确百分比。
- 提示：待补传、错误、加载采用统一 alert 组件风格。
- 游戏控件：颜色块、数字块、图片卡、声音卡、拼图块统一为大触控、清晰边界、活力色。

## 页面调整

### 绑定页

保留 4 位绑定码流程。页面顶部文案更像患者端入口，绑定码格加大，主按钮使用新主行动样式。

### 首页

标题从后台「工作台」气质调整为日常康复首页。患者与项目信息作为欢迎区，本周训练和健康数据用两个并列状态块展示，核心操作按钮突出「当前处方」「健康填报」「继续训练」。

### 当前处方

动作列表从后台卡片改为训练任务卡：动作名、类型、进度、最近记录和两个操作按钮。游戏动作进入时先显示分包加载进度条，再跳转游戏页。

### 训练记录与健康填报

保留输入字段，但改为更大的移动表单控件，减少后台 label/value 横排感。提交按钮固定为清晰主行动。

### 训练历史

顶部用两个统计块显示近 7 天、近 30 天。历史记录条目改为时间线式轻量列表。

### 游戏页

沿用已确认的海岛游戏视觉，并统一到全局 token。顶部状态条、按钮、反馈条、题目舞台、结果页指标都使用同一套形状和颜色。游戏页不再出现后台式卡片堆叠。

## 游戏分包加载

`app.config.ts` 已将游戏页面放入 `subPackages`：

```ts
{
  root: 'pages/game-session',
  pages: ['index']
}
```

本次新增一个窄 wrapper：

- 分包名：`pages/game-session`
- 页面地址：`/pages/game-session/index?actionId=<id>`
- 运行时优先调用微信 `wx.loadSubpackage`
- 监听 `onProgressUpdate` 更新 0-100 进度
- 成功后跳转游戏页
- 当前运行时不支持该 API 时直接跳转，并把进度视为 100
- 失败时留在处方页，展示错误提示和可重试入口

## 测试

- 新增分包加载 wrapper 单元测试：成功进度、失败错误、不支持 API fallback、URL 构造。
- 保留并运行小程序现有 Vitest 测试。
- 构建后检查 `dist/app.json` 中游戏仍在 `subPackages`，游戏资源仍位于 `dist/pages/game-session/assets`。
- 检查主包和游戏分包大小，避免资源回退到主包。
