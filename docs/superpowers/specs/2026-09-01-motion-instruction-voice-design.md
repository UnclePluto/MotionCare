# 运动动作说明预生成语音设计

> 状态：implemented
> 日期：2026-09-01
> 范围：为微信小程序 5 个正式运动动作的文字说明增加预生成语音、自动播放和手动重播能力。
> 关联：`docs/superpowers/plans/2026-09-01-motion-instruction-voice.md`
> 实施记录（2026-09-02, Codex）：代码提交 `3cefec4` 已合并至 `main`；微信开发版 `7.0.3` 已上传并由用户完成体验验收。

## 1. 背景

微信小程序当前在运动动作说明页只展示文字。患者进入训练前需要阅读较长的动作步骤和动作要点，对阅读能力较弱或视力不佳的患者不够友好。

本次为现有 5 个正式运动动作增加与文字说明配套的本地语音。语音作为辅助能力，文字仍是主要信息载体；语音播放失败不得阻塞动作预览或训练流程。

## 2. 已确认决策

1. 语音使用小米 `mimo-v2.5-tts-voicedesign` 预生成，不接入运行时在线 TTS。
2. 使用已经试听确认的成年普通话女声音色：自然、温和、清晰，语速稍慢，接近专业康复治疗师面对面指导。
3. 为当前 5 个正式运动动作各内置一段 M4A 音频。
4. 动作说明加载成功后自动播放一次，并保留手动重播按钮。
5. 医生后续修改动作说明文字时，本期不自动重新生成语音。
6. 不修改后端数据模型、API 或医生端动作编辑流程。

## 3. 范围

### 3.1 包含

- 原地高抬腿加摆臂：`motion-aerobic-high-knee`
- 坐站转移：`motion-balance-sit-stand`
- 坐姿划船：`motion-resistance-row`
- 腿部后踢：`motion-resistance-leg-kickback`
- 肩部推举：`motion-resistance-shoulder-press`
- 动作说明页自动播放、手动重播、播放状态和失败降级。
- 页面离开以及进入动作预览或训练前的播放停止和资源清理。

### 3.2 不包含

- 在线 TTS、服务端语音生成、语音资源管理后台。
- 医生修改文字后自动同步或重新生成语音。
- 训练过程中的逐步语音指令、节拍提示或动作识别反馈语音。
- 认知游戏、医生 Web 管理端或后端接口变更。

## 4. 音频资源

### 4.1 生成方式

- 模型：`mimo-v2.5-tts-voicedesign`
- 生成接口只在开发阶段使用，API Key 只从 `MIMO_API_KEY` 环境变量读取。
- 仓库只保存最终 M4A 文件，不保存 API Key、接口响应或临时 WAV 文件。
- 音频采用当前已经试听确认的版本。
- 输出格式为 AAC 单声道 M4A；当前试听文件采样率为 24 kHz。

### 4.2 口播内容

口播以当前正式动作库的步骤和动作要点为依据，为听觉理解做轻量口语化处理，例如将“45CM”读作“四十五厘米”，修正不适合朗读的缩写、标点和明显笔误。口播不得改变动作顺序、器材要求、安全要点或发力部位。

每段语音与动作 `source_key` 一一映射。运行时不读取说明文字生成文件名，也不根据动作名称模糊匹配。

### 4.3 资源位置与映射

最终音频放在运动训练公共功能目录下，由统一资源映射模块管理，例如：

```text
miniapp/src/features/motion-training/assets/audio/instructions/
  motion-aerobic-high-knee.m4a
  motion-balance-sit-stand.m4a
  motion-resistance-row.m4a
  motion-resistance-leg-kickback.m4a
  motion-resistance-shoulder-press.m4a
```

公共映射模块负责静态导入资源，并提供 `source_key -> 本地音频路径` 查询。未知或非正式 `source_key` 不播放语音，只保留文字说明。

## 5. 页面交互

### 5.1 自动播放

1. 页面先加载当前处方动作。
2. 动作有效、说明页面已进入可用状态且存在对应音频时，自动播放一次。
3. 加载中、动作无效、请求失败或没有音频映射时不自动播放。
4. 同一次页面访问中，页面从后台恢复或从系统遮挡恢复时不重复自动播放。
5. 如果页面实例切换到另一个动作，应停止旧语音，并为新动作执行一次新的自动播放。

### 5.2 手动重播

动作说明文字附近增加适老化按钮：

- 未播放或播放结束：`播放动作说明` 或 `重新播放说明`。
- 播放中：`正在播放说明`，按钮禁用，避免并发播放。
- 播放失败后：按钮恢复可用，患者可以再次尝试。

手动重播会停止尚未结束的旧播放实例，再从头播放当前动作语音。任意时刻最多只有一个动作说明音频实例处于活动状态。

### 5.3 导航与生命周期

以下操作发生前必须停止播放并销毁音频上下文：

- 点击“开始训练”。
- 点击“动作预览”。
- 页面卸载或切换到其他页面。
- 小程序页面进入隐藏状态。

停止或销毁失败不得阻断导航。

## 6. 状态与失败降级

语音是增强能力，不是训练入口的前置条件：

- 播放成功：播放状态结束后恢复重播按钮。
- 播放失败、超时或被系统中断：停止并销毁当前音频上下文，显示非阻塞提示“语音播放失败，请阅读文字说明”，同时恢复重播按钮。
- 患者主动导航导致的停止不显示错误提示。
- 文字动作说明始终展示，不因语音状态隐藏或替换。
- 未找到音频映射时不显示错误，不影响已有说明页和训练流程。

本期接受固定语音与未来被编辑文字可能不同步的限制，不增加动态生成能力。正式资源发布时必须确保 5 个当前动作的口播内容与当前标准动作说明一致。

## 7. 技术结构

复用并泛化现有 `miniapp/src/features/motion-training/alertAudio.ts` 播放生命周期。该模块现有的单实例播放、停止、销毁、错误、超时和过期回调处理继续作为公共底层；网络上传告警保留原有公开 API 和 15 秒超时，不改变现有训练行为。

泛化后的公共运动语音播放器职责包括：

- 按传入的本地音频路径创建、播放、停止和销毁 `Taro.createInnerAudioContext`。
- 处理播放结束、失败、超时、重播和过期回调。
- 允许网络告警和动作说明分别配置 15 秒与 90 秒超时。
- 向调用方返回播放是否自然完成，不直接控制页面状态或导航。

独立的动作说明资源映射模块负责 5 个 `source_key` 与本地音频路径的精确映射，不包含第二套音频上下文生命周期实现。

动作说明页只负责：

- 在动作加载成功后触发一次自动播放。
- 展示播放按钮、播放中状态和失败提示。
- 在导航和页面生命周期节点调用停止或销毁。

现有网络上传告警播放器的公开接口与行为保持不变，并组合复用泛化后的公共播放器；动作说明页直接组合资源映射与同一公共播放器。游戏语音播放器带有游戏全局静音状态和 15 秒短音频超时，不用于本功能。

## 8. 测试设计

### 8.1 资源与映射测试

- 5 个正式 `source_key` 均有唯一音频映射。
- 映射路径对应的 M4A 文件全部存在。
- 未知 `source_key` 返回无音频，不发生模糊匹配。

### 8.2 公共播放器单元测试

- 现有网络告警播放器测试全部继续通过，证明公开行为未回归。
- 公共播放器正常结束返回成功并销毁上下文。
- 公共播放器错误和可配置超时返回失败并销毁上下文。
- 重播或新播放会停止旧实例，旧回调不能覆盖新播放状态。
- `stop` 与 `dispose` 会停止活动实例，重复调用安全。
- 停止、销毁或创建上下文抛错时仍能收敛状态。

### 8.3 页面测试

- 有效正式动作加载完成后自动播放一次。
- 加载中、动作无效、加载失败和无映射动作不播放。
- 自动播放结束后可以手动重播。
- 播放中按钮禁用，结束或失败后恢复。
- 播放失败显示文字提示，但“开始训练”和“动作预览”仍可使用。
- 点击训练或预览前停止语音。
- 页面隐藏或卸载时停止并销毁语音。
- 页面恢复显示时不重复自动播放。
- 5 个正式动作都通过同一公共页面和资源映射工作。

### 8.4 完成前验证

- 运行小程序相关 Vitest 测试。
- 运行小程序完整测试套件。
- 运行开发构建和生产构建。
- 使用 `ffprobe` 验证 5 个音频均为可解析的 AAC 单声道 M4A。
- 在微信开发者工具或真机手动验证自动播放、重播、导航停止、静音和播放失败降级。

## 9. 验收标准

1. 5 个正式运动动作进入说明页后均自动播放对应的小米 MiMo 语音一次。
2. 患者可以清楚看到并使用手动重播按钮，播放期间不会叠音。
3. 开始训练、动作预览或离开页面后没有残留语音。
4. 语音失败不会阻塞训练，文字说明始终可读。
5. 非正式或未知动作保持原有文字体验，不发生错误播放。
6. 不新增后端接口、在线 TTS 依赖或前端密钥。
