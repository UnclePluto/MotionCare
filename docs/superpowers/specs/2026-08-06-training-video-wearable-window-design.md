# 训练视频时段穿戴趋势设计

## 1. 背景

当前肩部推举视频训练只记录训练日期和实际录像时长，没有记录患者实际开始、结束训练的精确时间。医生虽然可以在“训练视频”抽屉中播放视频并执行动作分析，但无法把这次训练与相同时段的穿戴测量点关联起来。

本设计为肩部推举视频训练补充手机端训练开始、结束时间，并在视频分析抽屉中展示该时间段内已经同步到 MotionCare 的心率、血压、血氧原始趋势和心率、血压统计。

## 2. 已确认决策

1. 一期只覆盖带视频的肩部推举训练，不修改游戏训练和普通训练记录。
2. 训练区间从第一次成功开始录像到最终完成训练，包含中途暂停时间。
3. 开始、结束时间以手机端时间为准，不以视频会话创建、上传、合并或分析任务的服务器时间替代。
4. 心率、血压、血氧按训练时间精确查询；一期不展示步数。厂商步数接口只提供日总量，不能生成真实训练时段趋势。
5. 视频分析页只读取系统已经同步的数据，不主动调用厂商接口，不触发后台同步。
6. 穿戴趋势采用“方案 A”：心率、血压、血氧通过页签切换，统计表固定显示在图表下方。
7. 时间缺失、三类指标全部无数据或查询失败时，整个穿戴区域不显示。
8. 历史视频不补算时间，不增加历史数据迁移逻辑。

## 3. 目标与非目标

### 3.1 目标

- 精确、可恢复地保存一次肩部推举视频训练的手机端开始和结束时间。
- 使用已有患者归属规则查询训练区间内的穿戴原始点。
- 展示心率、血压、血氧趋势。
- 展示心率、收缩压、舒张压的平均、最高、最低值和有效测量次数。
- 不影响视频上传、播放和动作分析现有链路。

### 3.2 非目标

- 不改造游戏训练或手工训练记录。
- 不记录多个暂停片段，也不从统计区间中扣除暂停时间。
- 不展示、估算或分摊训练时段步数。
- 不主动同步穿戴数据。
- 不对缺失测量点进行插值、补点或推算。
- 不补齐历史视频的开始、结束时间。
- 不输出医学诊断、阈值告警或健康结论。

## 4. 数据模型与时间语义

### 4.1 `TrainingVideo`

在 `TrainingVideo` 增加两个可空、带时区的字段：

- `training_started_at`：第一次录像真正启动成功时的手机端时间。
- `training_ended_at`：本次训练最终进入完成流程时的手机端时间。

字段保持可空，以兼容历史视频和尚未升级的小程序。字段缺失不影响视频处理，只表示该视频不能关联训练时段穿戴数据。

不把时间复制到 `TrainingRecord`。一期以 `TrainingVideo` 为唯一存储位置，避免为尚未纳入范围的游戏训练引入重复或不完整语义。

### 4.2 时间区间

- 统计区间为闭区间：`training_started_at <= measured_at <= training_ended_at`。
- 暂停、进入后台、恢复训练不改变 `training_started_at`，暂停时段仍属于本次训练区间。
- 视频上传、服务端合并、七牛上传和动作分析时间均不属于训练区间。
- `training_date` 继续表示训练开始所在的手机本地自然日。
- 允许训练跨午夜结束；跨午夜不改变 `training_date`。

### 4.3 训练跟踪序列化

医生端训练跟踪的 `recent_records` 中，为已关联视频的记录增加：

- `training_started_at`
- `training_ended_at`

前端使用这两个字段展示抽屉顶部的训练时段，不依赖穿戴查询成功。旧视频返回 `null`。

## 5. 小程序记录与恢复

### 5.1 本地会话

`PendingShoulderPressSession` 增加：

- `trainingStartedAt?: string`
- `trainingEndedAt?: string`

使用带手机时区偏移的 ISO 8601 字符串持久化，例如 `2026-08-06T09:32:14+08:00`，不能只保存无时区的本地时间文本，也不能丢失用于确定手机本地自然日的偏移信息。

### 5.2 开始

第一次调用录像器并确认启动成功后：

1. 读取手机当前时间。
2. 写入 `trainingStartedAt`。
3. 使用同一手机时间重新计算并写入 `trainingDate`。
4. 立即保存本地待上传会话。

暂停后继续训练不得覆盖该值。录像器未能启动时不得写入开始时间。

摄像页可能在午夜前打开、午夜后才真正开始，因此不得继续沿用进入页面时预先生成的日期。

### 5.3 结束

患者点击“完成训练”且已通过现有完成条件，或训练达到现有自动结束条件时：

1. 立即读取手机当前时间并写入 `trainingEndedAt`。
2. 持久化本地会话。
3. 再停止录像、保存最后分段并进入上传流程。

这样可以排除停止录像、文件保存和上传耗时。若尾段保存或上传失败，重试继续使用首次写入的结束时间，不得重新生成。

### 5.4 崩溃和上传恢复

- 开始、结束时间与现有分段清单一起写入本地存储。
- 小程序重启后恢复上传时原样提交两个时间。
- 重试创建会话、查询状态、上传分段和完成会话均不得修改时间。
- 放弃本地会话并重新训练时，随原会话一起清理时间；新训练生成新的时间。

## 6. 患者端视频会话 API

### 6.1 创建会话

`POST /api/patient-app/training-video-sessions/` 增加可选字段：

```json
{
  "training_started_at": "2026-08-06T09:32:14+08:00"
}
```

新版小程序必须提交该字段。后端保存到 `TrainingVideo.training_started_at`。重复创建同一 `client_session_id` 时：

- 相同开始时间按现有幂等语义返回原会话。
- 已保存时间与重试值冲突时拒绝覆盖。

### 6.2 完成会话

`POST /api/patient-app/training-video-sessions/{video_id}/finalize/` 增加可选字段：

```json
{
  "training_ended_at": "2026-08-06T09:41:27+08:00"
}
```

新版小程序必须提交该字段。后端在现有分段、时长校验之外校验并保存结束时间。重复完成请求提交相同时间时保持幂等；冲突值不得覆盖原值。

### 6.3 校验

- 时间文本必须包含明确的 UTC 偏移或 `Z`，不接受无时区时间。
- `training_ended_at` 必须晚于 `training_started_at`。
- 两者墙钟跨度不得超过 24 小时，用于拒绝明显错误的手机时间或损坏的本地会话。
- `actual_duration_seconds` 不得明显大于开始至结束的墙钟跨度；允许 5 秒编码与计时误差。
- `training_date` 必须等于 `training_started_at` 在其提交偏移下的自然日。
- 校验失败返回明确的患者可理解错误，不得回退为服务器时间。

字段在接口层保持可选仅用于兼容旧版本；只要任一字段缺失，视频仍可按原流程完成，但不会产生穿戴趋势。

## 7. 训练时段穿戴查询

### 7.1 接口

新增：

```text
GET /api/training/videos/{video_id}/wearable-window/
```

接口使用现有 `get_training_video_for_user` 权限边界，先确认当前管理员或医生能够访问该视频及患者。

### 7.2 数据范围

- 患者取自视频关联的 `ProjectPatient.patient`。
- 只查询 `WearableMeasurement.attribution_status = attributed` 且归属该患者的原始点。
- 时间范围使用 `TrainingVideo.training_started_at` 和 `training_ended_at`。
- 设备绑定、解绑或换绑发生在训练区间内时，沿用现有测量点归属结果，不越权拼接其他患者数据。
- 不查询 `WearableDailySource`，不返回步数。
- 不调用厂商 OpenAPI，不创建同步任务。

### 7.3 响应

有数据时返回稳定结构：

```json
{
  "available": true,
  "training_started_at": "2026-08-06T01:32:14Z",
  "training_ended_at": "2026-08-06T01:41:27Z",
  "metrics": {
    "heart_rate": {
      "points": [
        {"measured_at": "2026-08-06T01:33:00Z", "value": 86}
      ],
      "statistics": {
        "average": 89.4,
        "maximum": 118,
        "minimum": 67,
        "count": 8
      }
    },
    "blood_pressure": {
      "points": [
        {
          "measured_at": "2026-08-06T01:34:00Z",
          "systolic": 126,
          "diastolic": 78
        }
      ],
      "statistics": {
        "systolic": {"average": 126.3, "maximum": 132, "minimum": 121},
        "diastolic": {"average": 78.0, "maximum": 82, "minimum": 74},
        "count": 3
      }
    },
    "blood_oxygen": {
      "points": [
        {"measured_at": "2026-08-06T01:35:00Z", "value": 97}
      ]
    }
  }
}
```

规则：

- 原始点按 `measured_at` 升序返回。
- 平均值使用十进制定点的四舍五入规则保留一位小数，避免依赖二进制浮点或语言默认的银行家舍入。
- 最大值、最小值和次数保持整数。
- 血压只统计同时存在收缩压和舒张压的有效成对测量。
- 某个指标无数据时，对应指标键可省略。
- 时间缺失或三类指标全部无数据时返回 `200 {"available": false}`，前端据此不渲染穿戴区域。
- 接口异常使用正常错误状态码；前端将其视为非阻断失败并隐藏穿戴区域。

## 8. Web 视频分析抽屉

### 8.1 基本信息

“训练视频”抽屉顶部描述区增加“训练时段”：

- 同一自然日显示 `HH:mm:ss–HH:mm:ss`。
- 跨自然日时两端都显示月日和时间。
- 任一时间缺失时不显示该描述项。

### 8.2 趋势区

视频播放器和现有“动作分析”区域保持原样。在动作分析下方增加“训练时段穿戴趋势”：

- 只在 `available = true` 时渲染。
- 使用心率、血压、血氧页签切换，顺序固定。
- 只创建有数据的页签，默认选中第一个可用指标。
- 复用项目现有 `@ant-design/charts` 趋势图能力和视觉规范。
- 心率：单线，单位“次/分”。
- 血压：收缩压、舒张压双线，单位“mmHg”，提供固定图例。
- 血氧：单线，单位“%”。
- 横轴显示训练区间内的本地时间；悬停提示展示完整时间与数值。
- 不对缺失点插值，不生成虚假采样点。

### 8.3 统计表

图表下方固定放置“训练时段统计”表，列为：

- 指标
- 平均
- 最高
- 最低
- 测量次数

行规则：

- 心率有数据时显示“心率”行。
- 血压有数据时分别显示“收缩压”“舒张压”两行，两行使用同一个血压测量次数。
- 血氧不进入统计表。
- 没有心率和血压统计时，隐藏整张统计表，但血氧趋势仍可正常显示。

### 8.4 加载与失败

- 打开视频抽屉时，视频地址、动作分析结果和穿戴数据可以并行请求。
- 每次重新打开某个视频抽屉时重新查询穿戴数据，不保留会遮蔽后续同步结果的长期缓存。
- 穿戴请求不得阻塞视频播放或动作分析。
- 加载期间不预留空白穿戴区域，避免无数据时页面闪烁。
- 无数据或请求失败时不显示穿戴区域，也不弹出阻断提示。
- 不提供同步、重新同步或刷新穿戴数据按钮。

## 9. 安全与性能

- 医生端查询必须复用视频访问权限，不能仅依赖前端传入患者编号。
- 返回数据只包含图表和统计所需的规范化值，不返回厂商原始载荷、设备真实标识或访问凭据。
- 查询限定单次训练区间，使用患者、指标类型和测量时间过滤；沿用现有测量索引并在实施时用查询计划确认无需新增重复索引。
- 不记录或打印厂商 Token、视频私有下载地址和穿戴原始载荷。

## 10. 测试与验收

### 10.1 小程序

- 首次成功开始录像只写入一次开始时间。
- 录像启动失败不写入开始时间。
- 摄像页跨午夜后首次开始时，训练日期更新为开始时间对应的手机本地自然日。
- 暂停、继续不改变开始时间。
- 正常完成和自动完成写入结束时间。
- 保存尾段失败、上传失败和重启恢复上传不改变两个时间。
- 放弃旧会话重新训练会生成新的时间。
- 创建和完成 API 请求携带带时区时间。

### 10.2 后端

- migration 与模型字段可空，历史数据不回填。
- 创建会话保存开始时间，重复创建幂等，冲突值拒绝覆盖。
- 完成会话保存结束时间，重复完成幂等，冲突值拒绝覆盖。
- 缺少时区、结束不晚于开始、超过 24 小时、日期不一致和时长异常均拒绝。
- 视频处理失败或重试不修改训练时间。
- 穿戴接口覆盖时间边界、排序、患者权限和绑定归属。
- 心率平均/最高/最低/次数正确。
- 血压成对统计、收缩压和舒张压平均/最高/最低正确。
- 单指标缺失时只返回可用指标。
- 时间缺失或全部无数据时返回 `available = false`。
- 不查询步数，不触发同步。

### 10.3 Web

- 有时间时正确显示训练时段，无时间时不显示该描述项。
- 只显示存在数据的指标页签，默认选择第一个。
- 血压显示收缩压、舒张压双线。
- 统计表只显示有统计数据的行。
- 只有血氧数据时显示趋势但不显示统计表。
- 无数据和请求失败时不渲染穿戴区域。
- 穿戴请求失败不影响视频播放、动作分析及抽屉其他内容。

### 10.4 回归

- 现有分段录制、后台上传、恢复上传、服务端合并和七牛上传流程通过。
- 医生端视频私有播放和动作分析流程通过。
- 现有穿戴健康页原始趋势、日汇总和研究汇总流程通过。

## 11. 验收口径

1. 新版小程序完成一次肩部推举后，`TrainingVideo` 保存手机端开始、结束时间。
2. 暂停时间包含在训练区间内，上传和服务端处理时间不包含。
3. 医生打开视频分析抽屉时，可切换查看训练时段内已经同步的心率、血压、血氧趋势。
4. 统计表正确展示心率、收缩压、舒张压的平均、最高、最低和测量次数。
5. 页面不展示训练时段步数，不主动同步穿戴数据。
6. 时间缺失、全部无数据或穿戴查询失败时，穿戴区域完全不显示。
7. 旧视频、游戏训练、现有视频处理和动作分析行为不受影响。
