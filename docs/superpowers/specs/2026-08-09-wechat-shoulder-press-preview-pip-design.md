# 微信小程序肩部推举动作预览与录像画中画设计

## 1. 背景

当前微信小程序把肩部推举示例视频直接放在动作介绍页，患者只有“进入摄像训练”一个入口；
进入录像页后只能看到前置摄像头画面，训练期间无法继续对照示范动作。录像页虽然已经展示
录像计时和分段上传状态，但预计处方时长只用于判断何时允许完成，没有明确的剩余倒计时，
也不会在达到处方时长时自动完成。

本设计将“了解动作”“独立预览”和“录像训练”分开。患者可以直接开始训练，也可以先打开
独立预览页；进入录像后，以前置摄像头为主画面，在右上侧静音循环播放示范视频，并允许患者
滑动收起。左上侧固定展示已训练时间与剩余时间，患者可以提前结束，倒计时归零时系统自动
结束并进入现有上传流程。

## 2. 已确认决策

1. 一期只覆盖 `source_key = motion-resistance-shoulder-press` 的肩部推举，不修改其它运动动作。
2. 处方动作现有 `video_url` 是唯一示范视频来源，不新增视频字段。
3. 示例视频可以存储在七牛云；`video_url` 必须是小程序可直接播放的稳定 HTTPS CDN 地址，
   不保存即将过期的临时签名地址。
4. 动作介绍页提供“开始训练”和“动作预览”两个入口；没有 `video_url` 时隐藏“动作预览”，
   仍允许直接开始训练。
5. 独立预览页和录像页中的示范视频都始终静音、自动循环播放。
6. 录像页左上侧固定显示正计时和倒计时；右上侧显示示范视频。
7. 示范视频可向右滑出隐藏；隐藏后右边缘保留“向左恢复示范”的提示，向左滑后还原。
   滑动只影响示范视频，计时区保持原位，录像和计时不中断。
8. 倒计时使用创建本次训练会话时保存的处方动作时长快照。
9. 患者可提前点击“结束训练”，二次确认后结束；倒计时归零后自动结束，不再确认。
10. 手动结束和自动结束复用同一幂等结束流程，继续进入现有强制上传页。
11. 不新增后端模型、接口或 H5 患者端功能，不改变医生端视频与健康数据展示。

本设计局部覆盖关联设计中的两项旧行为：肩部推举不再要求达到处方时长后才能手动完成；
`training_ended_at` 的正常结束语义扩展为“患者确认手动结束或处方倒计时自动结束时的手机端
时间”。该字段仍允许缺失，且仍不参与医生端健康观察窗口计算。

## 3. 页面结构

```text
当前处方动作列表
  -> 肩部推举动作介绍页
       -> 开始训练 -> 录像页 -> 强制上传页 -> 完成结果
       -> 动作预览 -> 独立预览页
                         -> 关闭预览 -> 返回动作介绍页
                         -> 开始训练 -> 录像页 -> 强制上传页 -> 完成结果
```

### 3.1 动作介绍页

现有 `pages/shoulder-press/index` 继续负责：

- 根据 `actionId` 重新读取当前处方并确认动作仍是肩部推举；
- 展示动作名称、动作说明和训练准备事项；
- 在动作有效时始终展示“开始训练”；
- 仅在 `video_url` 非空时展示“动作预览”。

动作介绍页不再内嵌视频播放器。点击“开始训练”沿用现有录像页地址；点击“动作预览”只传递
`actionId`，不把 CDN 地址拼入路由参数。

### 3.2 独立预览页

新增肩部推举预览页面并注册到小程序页面配置。页面根据 `actionId` 重新读取当前处方，复用
现有的肩部推举动作解析规则，避免使用已经失效或不属于当前处方的动作数据。

页面包含：

- 主区域示范视频：`autoplay`、`loop`、`muted`，保持竖屏适配；
- “关闭预览”：返回动作介绍页；
- “开始训练”：用当前 `actionId` 进入录像页，不把预览页保留为训练完成后的返回目标；
- 视频加载失败状态：显示“视频加载失败”和“重新加载”，两个底部动作继续可用。

如果重新读取处方后动作无效或 `video_url` 已缺失，页面不尝试播放旧地址，提示患者返回当前
处方。系统返回键与“关闭预览”语义一致。

### 3.3 录像页

现有 `pages/shoulder-press/camera` 继续拥有摄像权限、分段录像、后台分段上传、结束录像和跳转
强制上传页的职责。在摄像头预览容器内增加两个互相独立的覆盖层：

- 左上侧固定计时卡片：第一行“已训练”，第二行“剩余”；
- 右上侧示范视频：使用当前动作的 `video_url`，静音循环播放。

底部使用固定的“结束训练”按钮。现有分段上传计数和错误状态可以保留在摄像画面之外，不与
计时卡片争抢位置。

默认进入录像页时示范视频处于展开状态。患者在示范小窗上向右滑达到手势阈值后，小窗平滑
滑出右侧；右边缘留下窄的“向左恢复示范”提示。患者在该提示上向左滑达到阈值后恢复小窗。
竖向滚动和轻触不应误触发隐藏。显示状态只属于当前录像页面，不写入后端或长期本地存储。

小程序当前基础库版本为 3.16.0。摄像头与视频画中画必须使用微信同层渲染可用的普通组件树
与绝对定位实现，并在微信开发者工具、iOS 和 Android 真机验证层级、裁切及手势事件；不能只
依据 Web 预览判断可用。

## 4. 视频资源规则

`video_url` 继续来自当前处方接口的动作快照。七牛云侧需要满足：

- CDN 域名已开启 HTTPS，证书覆盖实际播放域名；
- 视频对象和 CDN 地址能在患者训练期间稳定访问；
- CDN 域名加入微信小程序合法业务域名；
- 响应支持视频播放所需的范围请求和正确媒体类型；
- 视频编码使用目标微信机型可播放的格式。

本期不新增七牛上传管理页面、签名刷新接口或视频转码任务。医生或管理员仍通过现有动作资料
配置能力维护 `video_url`。如果后续必须使用私有空间和短期签名，应另行设计由后端实时签发
播放地址的接口，不能把临时地址长期写入处方快照。

## 5. 计时语义

### 5.1 开始

计时不能在页面加载、摄像头初始化或患者点击按钮时提前启动。只有录像器返回启动成功后，
才执行以下动作：

- 首次写入现有 `training_started_at` 手机端时间；
- 开始显示正计时；
- 从会话现有 `expectedDurationSeconds` 开始显示倒计时。

`training_started_at` 的语义继续遵循固定健康观察窗口设计：第一次真实录像启动成功时的手机端
时间，暂停、继续和分段切换都不得覆盖。

### 5.2 正计时与倒计时

正计时使用现有有效录像时长，而不是简单累加每次界面刷新事件：

```text
elapsed = 已保存分段时长 + 当前活动录像段的实际时间差
remaining = max(0, expectedDurationSeconds - elapsed)
```

每秒刷新只负责触发显示更新，真实值由时间差重新计算，从而避免定时器延迟造成累计漂移。
现有进入后台自动暂停录像的行为保持不变；暂停期间不增加有效录像时长，回到前台并继续训练后
再继续正计时和倒计时。15 秒录像分段切换和后台分段上传不得重置两个计时值。

`expectedDurationSeconds` 继续在会话创建时从处方动作时长生成并规范到 1–2400 秒。既有 40 分钟
录像安全上限和相机提前停止保护继续保留，不能因为新增倒计时移除。

### 5.3 结束

结束入口包括：

- 手动结束：录像已经成功开始后，“结束训练”始终可用，不再要求达到处方时长；点击后先二次
  确认，患者确认才执行结束；
- 自动结束：`elapsed >= expectedDurationSeconds` 时直接执行结束，不弹确认；
- 安全结束：达到既有相机安全截止时间时继续强制结束。

三种入口必须调用同一个受互斥锁保护的结束函数。结束函数只允许执行一次：停止录像、等待尾段
落盘、等待当前后台上传稳定、记录可选 `training_ended_at`，然后跳转现有强制上传页。正常手动
结束和自动结束都应尽力写入手机端结束时间；意外退出仍允许该字段缺失，且结束时间继续不参与
医生端健康图表窗口计算。

患者取消手动结束确认后继续录像，计时不重置。停止和跳转过程中按钮进入忙碌状态，不允许
重复点击。

## 6. 状态与组件边界

为避免继续扩大录像页职责，实施时应提取小而明确的单元：

- `ShoulderPressPreview` 页面只负责解析动作、预览视频和两个导航动作；
- `ShoulderPressTrainingOverlay` 只负责计时展示、示范视频展示状态和滑动手势；
- 纯函数负责计算 `elapsed`、`remaining`、自动结束条件和手势方向；
- 现有录像器与上传流程继续负责媒体分段和网络生命周期，不负责 UI 展示；
- 录像页协调上述单元，并保留唯一的开始、暂停、结束入口。

组件之间只传入当前动作、计时值、录像状态以及结束回调。示范视频加载失败不能修改录像会话，
手势状态也不能写入视频上传清单。

## 7. 异常与降级

| 场景 | 行为 |
| --- | --- |
| 动作介绍页缺少 `video_url` | 隐藏“动作预览”，保留“开始训练” |
| 独立预览视频加载失败 | 显示失败与重试；保留关闭和开始训练 |
| 录像页示范视频加载失败 | 显示非阻塞失败提示并允许隐藏；录像与计时继续 |
| 摄像头或麦克风权限被拒绝 | 不启动录像和计时；提示授权、重试或返回 |
| 录像启动失败 | 不写入开始时间；允许重试 |
| 手动结束被取消 | 保持录像和计时，不产生结束时间 |
| 结束流程重复触发 | 忽略后续触发，只保留第一次结束操作 |
| 尾段保存或上传失败 | 沿用现有尾段重试和强制上传页恢复流程 |
| 小程序意外退出 | 沿用现有待上传会话恢复；`training_ended_at` 允许缺失 |

示范视频属于辅助信息。除动作和摄像头本身无效外，任何示范视频播放错误都不能阻止患者完成
训练。

## 8. 测试与验收

### 8.1 自动化测试

- 肩部推举且存在 `video_url` 时动作介绍页显示两个入口；缺失时只显示“开始训练”。
- 其它动作路由和按钮文案保持原有行为。
- 独立预览页视频为静音、自动播放和循环；关闭返回介绍页，开始训练进入录像页。
- 预览页重新读取处方并拒绝无效、过期或不再属于当前处方的动作。
- 视频加载失败时渲染重试状态，不禁用开始训练。
- 录像启动成功前两个计时不运行；成功后使用有效录像时长计算正计时与倒计时。
- 暂停、继续和 15 秒分段切换不重置计时；暂停期间不累计有效录像时长。
- 手动提前结束需要确认；取消后不结束，确认后只调用一次结束流程。
- 达到处方时长时自动结束；与手动点击、相机安全截止并发时也只能结束一次。
- 展开态向右滑隐藏，隐藏态向左滑恢复；反向、短距离和竖向手势不切换状态。
- 示范隐藏或恢复时左侧计时区结构与位置不变，录像状态和上传清单不变。
- 缺少或无法播放示范视频时，录像、计时、结束和上传流程仍可完成。
- 现有录像分段、后台上传、尾段失败恢复、固定健康观察窗口和训练完成测试保持通过。

### 8.2 微信开发者工具与真机验收

- 七牛 HTTPS CDN 地址在微信开发者工具及至少一台 iOS、一台 Android 真机可播放。
- 独立预览页静音循环，关闭和开始训练导航正确。
- 前置摄像头与右上侧示范视频可以同屏运行，无黑屏、层级倒置或明显掉帧。
- 左侧计时固定，右侧示范隐藏与恢复时不发生跳位。
- 不同屏幕尺寸和安全区域下，顶部覆盖层不遮挡系统导航，底部结束按钮可点击。
- 正计时、倒计时、暂停继续、提前结束、自动结束与强制上传符合本设计。
- 权限拒绝、视频失败、尾段失败和上传失败均可恢复，且不会生成重复训练记录。

## 9. 非目标

- 不把动作预览和画中画扩展到其它运动动作。
- 不开发患者 Web/H5 训练端。
- 不新增患者选择示范视频、声音或画中画尺寸的设置。
- 不支持拖动画中画、任意缩放或记忆隐藏状态。
- 不修改视频分析算法、医生端视频播放或穿戴健康观察窗口。
- 不重构与本功能无关的游戏训练、普通训练或设备管理代码。
