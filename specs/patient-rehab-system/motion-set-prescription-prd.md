# 运动处方按组计数、组间休息与逐组录像分析

> 状态：approved；规格已获用户整体批准，功能尚未实施。
> 日期：2026-09-16
> 适用范围：坐站转移、坐姿划船、腿部后踢、肩部推举。

## Problem Statement

医生目前只能用时长配置运动处方，无法准确表达“每组做多少个、每次做多少组、每周做多少次”。用户也只能按时间结束跟练，不能在做完一组后确认完成、获得明确的组间休息指导，再开始下一组。

现有录像、训练记录和动作分析以一段视频为基本单位。直接将一次运动拆成三段视频，会把三组误算为三次运动；医生也难以判断这些视频属于哪一次运动、哪一组。网络慢、中途退出、改方和跨天补传进一步造成完成口径、录像归属和健康曲线范围不清。

需要将一次运动、组和录像尝试分开表达：按次统计完成，按组录制与分析，个数计算继续异步执行。现有生效处方统一切换新模式，同时保留可追溯的旧数据。

## Solution

将坐站转移、坐姿划船、腿部后踢、肩部推举的处方改为每组个数、每次组数和每周次数。新开默认 10 个、3 组、每周 3 次，医生可调整；腿部后踢的 10 个表示左右每侧各 10 个，两侧做完合为一组、一个视频。椰林步道模拟（原地高抬腿＋摆臂，即本次讨论中的“行走”）保持按时长模式。

用户自行计数，点击“完成本组”结束该组录像。非最后一组后休息三分钟，不可跳过；开始时播报休息时长和剩余组数，剩余三十秒提醒一次，最后五秒逐秒倒数，伴随轻柔滴答音。休息结束后等待点击“开始下一组”，才重新录制。最后一组后直接进入完成页。

每组录像独立上传、独立异步分析。上一组安全保存后，即使尚未上传成功，也允许休息结束后开始下一组；存储不足时阻止新组开始。规定全部组做完且视频全部上传成功后计入每周完成一次，不等待分析。后台按一次运动汇总，展开查看各组；导出每组一行，保留所属运动编号和组序号。

现有生效处方通过自动生成新版本完成切换，四动作补为每组 10 个、每次 3 组，保留医生原每周次数。仅四动作的旧训练记录标记作废、退出正常统计和导出，原始记录、分析和录像保留备查；行走和认知游戏保持原状。

## User Stories

1. 作为医生，我希望四个计数组动作使用个数、组数和每周次数开具处方，以便准确表达运动安排。
2. 作为医生，我希望新开处方默认每组 10 个、每次 3 组、每周 3 次，以便减少重复填写。
3. 作为医生，我希望逐动作调整三个参数，以便配置不同的运动计划。
4. 作为医生，我希望参数只接受有效正整数，以便避免零、小数或无效输入导致执行歧义。
5. 作为医生，我希望腿部后踢明确显示“每侧个数”，以便清楚表达左右两侧各自的目标。
6. 作为医生，我希望行走继续使用时长和每周次数，以便保留该动作已有的执行方式。
7. 作为医生，我希望调整处方生成新版本，以便历史训练仍能追溯当时的安排。
8. 作为医生，我希望现有生效处方自动切换新模式，以便无需逐人重新开具。
9. 作为医生，我希望现有处方切换时保留原每周次数，以便既有频次不被默认值覆盖。
10. 作为用户，我希望开始前看到每组或每侧目标、总组数及当前组序号，以便知道需要完成什么。
11. 作为用户，我希望继续查看动作说明和教学视频，以便理解动作要求。
12. 作为用户，我希望点击开始后才进行本组运动和录制，以便能先做好准备。
13. 作为用户，我希望自行计数后点击“完成本组”，以便按实际完成情况结束这一组。
14. 作为用户，我希望计数组动作不因处方倒计时自动完成，以便执行依据始终是组和个数。

17. 作为用户，我希望休息开始时听到休息时长和剩余组数，以便不必持续阅读屏幕。
18. 作为用户，我希望剩余三十秒时听到一次提示，以便准备下一组。
19. 作为用户，我希望最后五秒听到逐秒倒数，以便知道休息即将结束。
20. 作为用户，我希望休息期间有轻柔滴答音，以便感知计时仍在进行。
21. 作为用户，我希望提示语音不会被滴答声盖住，以便听清关键信息。
22. 作为用户，我希望休息必须满三分钟才能开始下一组，以便按既定流程执行。
23. 作为用户，我希望休息结束后可以稍晚再点击开始，以便在准备好时继续，而不是被自动录制。
24. 作为用户，我希望休息和等待点击期间不录制，以便每组视频只包含对应运动。

## Implementation Decisions

### 领域边界与模块职责

- 一次运动绑定一个患者项目关系、一个处方版本和一个动作快照，拥有固定计划组数、每组目标、计数单位、原运动日期和唯一客户端编号。
- 一组以所属运动和组序号唯一定位；“组已做完”和“视频已上传”分别记录。未开始的组可显示占位，实际实体按需创建。
- 每次重做拥有独立录像尝试编号，沿用原组序号。旧尝试放弃后不能被延迟上传或回调重新激活，也不能清理新尝试的文件。
- 采用新增一次运动和组实体、复用现有视频与训练记录链路的方案。每个正式组视频仍关联现有一条训练记录和独立分析结果；父级运动负责完成次数，组记录不能直接充当运动次数。
- 处方模块负责模式与版本；运动流程负责组状态、休息与恢复；上传模块负责独立组视频；后台追踪、健康查询及导出负责按次汇总和按组展现。

### 处方与参数

- 四个动作使用计数组模式，行走继续按时长；新参数及计数单位保存为处方快照，不随动作库或后续改方漂移。
- 新开默认每组 10 个、每次 3 组、每周 3 次；腿部后踢为每侧 10 个，一组合计目标 20 个。
- 每组个数和组数只允许有效正整数，采用现有整数存储边界，不新增临床剂量上限。避免根据用户填写的组数一次性分配大量实体或缓存。
- 每周次数沿用现有前端 1–21 和后端正整数兼容行为；现有生效处方切换保留医生原每周次数。
- 四动作新模式不要求分钟值、不按分钟自动完成，不将个数换算成虚构的预计运动分钟数。
- 调整处方继续生成新版本；自动切换也生成可追溯的新版本，记录系统迁移来源，保留旧快照，不伪造医生主动操作。

### 训练、休息与中断

- 摄像头启动成功才记录实际组开始时间；点击完成后停止录制，安全保存尾段、结束时间和完成声明，再进入休息或完成页。
- 保存失败不能虚报录像已安全保存；完成按钮需防止连点。
- 非末组休息三分钟，以该组实际结束时间加一百八十秒计算，不可跳过；休息结束必须手动点击下一组。
- 训练中切后台、锁屏或来电造成录像中断，当前组未完成，清理片段后重做。正常连续分片和单纯上传慢不属于组中断。
- 当天返回保留已完成组，从未完成组重做；跨天退出后返回开启新一次。全部组已做完、仅隔天补传属于原次运动。
- 当天回来前处方已调整，旧次保留为部分完成，已完成组可补传；新运动按新处方从第一组开始。
- 不提供组内暂停后拼接恢复的业务操作；未完成组不发布、不分析，不与重做片段拼接。

### 休息音频与日期

- 开始休息播报时长和剩余组数，剩余三十秒提示一次，最后五秒逐秒倒数，结束提示点击开始。
- 滴答声低音量播放，语音时暂停，播报后按当前剩余时间恢复；结束休息、退出或开始录像前停止。
- 复用预生成语音和现有私有素材签名机制，使用固定短句及数字读音组合，不接入运行时在线语音合成。
- 休息切后台或锁屏照常经过，返回不补播过时提示。前台声音为验收保证；不承诺后台或锁屏持续声音。音频失败保留文字和正确计时，不阻塞操作。
- 日期使用上海时区，周范围为周一到周日，运动日期固定为首次实际开始日期。
- 连续运动自然经过午夜不强行打断，允许未离开的这次完成并归开始日期；退出后跨天返回仍按新一次处理。
- 保留现有单视频三十分钟及分片、容量保护作为单组技术边界；提前提示，达到边界安全停止并按未完成处理，不能将其用作自动完成条件。

### API、上传与恢复契约

- 公共业务接口需表达创建运动、开始组尝试、确认本组、放弃尝试、查询进度和恢复补传；服务端校验患者归属、处方资格、有效组序号、尝试状态及一致的时间快照。
- 所有改变状态的请求使用稳定幂等标识；重复完成、重复上传、异步回调重放均不得增加组数、视频数或完成次数。
- 升级现有单录像缓存为患者隔离的多组持久化队列，记录运动、组和尝试编号、实际时间、完成声明、文件及上传状态。
- 上一组安全保存后，下一组可在休息结束时开始；网络失败保留待上传内容，存储不足阻止新组开始。
- 本地可恢复视频保留至该组最终视频可用，避免服务器暂存过期后失去补传来源。容量检查覆盖所有待确认组。
- 上传完成指服务端合并、七牛私有视频可用并绑定该组记录成功，不能仅依据最后一个分片接收成功。
- 暂存过期但本地完整组文件仍在时，允许新的技术上传尝试，保留原组及完成声明，不要求重做、不重复计次。
- 唯一剩余视频因清除应用等原因丢失时，明确显示上传无法完成，不能虚构成功或计入完整完成。
- 新运动或新组检查当前处方；已完成组补传校验原次运动及原授权快照，不能单纯因处方不再生效而拒绝。解绑等现有权限和清理规则继续适用。

### 完成统计与异步分析

- 全部计划组做完且各组视频均上传成功，父级运动才计一次；上传待完成时显示“运动已做完，视频待上传”。
- 补传成功计入原运动日期对应的周；只完成部分组记录部分完成，不增加每周完成次数。
- 任一正式组视频可用后即可触发该组异步分析，不等待其他组；客户端不做同步个数校验、不等待分析结果。
- 分析成功、失败或计数不达目标不撤销已满足上传条件的完成计次，也不要求用户重新做已完成组。
- 继续复用现有独立串行动作分析、租约和结果回写机制，不新增同步算法调用或产品层面的重新分析入口。
- 腿部后踢当前算法按左右通道合计并提供带侧别明细；显示每侧目标与合计结果时必须区分口径，不以合计数冒充单侧数。

### 后台、健康数据与导出

- 后台一次运动一条汇总记录，分别展示已做完组数、已上传组数及完成状态；展开各组独立视频、骨架视频、分析结果和健康曲线。
- 未返回的分析数为空，不能使用零或目标数占位；沿用医生对本组分析结果的编辑能力，编辑不改变用户完成声明和上传状态。
- 每组健康窗口使用实际开始至实际结束后五分钟；上传、处理或分析延迟不能移动窗口，相邻组窗口允许重叠。
- 汇总运动时长以各组实际录像秒数求和，排除休息和等待，不能逐组分钟向上取整后再累计。
- 正常运动导出每个有效已完成组一行，包含运动编号、组序号、计划组数、每组或每侧目标、原日期、所属运动完成状态及现有分析和健康字段。部分完成运动中的有效组可导出。
- 不恢复此前已移除的无关导出列；行走和认知游戏保持原粒度。
- 作废旧记录退出正常统计与导出，受原权限约束的查看入口保留记录和视频备查；不绕过解绑等既有规则。

### 迁移与兼容

- 迁移可预览影响数量、可重复执行，记录切换标记并逐患者锁定生效处方，避免重复生成新版本或重复作废。
- 受影响生效处方中四动作补 10 个、3 组，保留原周频次；行走、游戏参数原样复制，建立迁移前后动作映射维持未改变动作的原统计。
- 已归档、未生效、已终止处方不自动重新激活；未来开具或激活时校验新参数规则。历史快照不改写。
- 仅按旧模式及切换标记作废四动作旧记录，记录时间和原因，保留原记录、分析及视频，不按日期粗暴删除。
- 切换前已建立的旧录像可继续收尾，但成为作废历史，不能借延迟上传进入新统计。
- 切换后旧客户端不得新建四动作的按时长运动，应显示更新提示；行走和游戏仍可使用原流程。
- 后端先支持新旧模式和旧会话收尾，再启用处方切换和新客户端；回退必须能识别新模式数据。
- 保持患者、项目绑定、鉴权、CSRF、私有视频访问和解绑语义；本次不修改这些领域边界。

### 演示模式

- 四动作演示采用相同组数、手动完成、三分钟休息、语音与滴答体验，不缩短休息。
- 延续演示隔离：不录制、不生成视频文件、不上传、不写真实训练记录；演示完成不能冒充真实上传成功。
- 行走演示保留按时长模式。

## Testing Decisions

### 测试边界

测试方案沿用用户已整体批准的设计，以“医生开具或迁移处方 → 用户逐组运动、休息与上传 → 后台汇总、查看和导出”为一个主验收闭环。优先复用现有公共 API 集成测试和页面交互测试两个高层入口，不另建仅供测试使用的业务接口，不以私有函数调用次数或内部对象结构作为验收结果。

后端测试通过真实 API 和可观察的状态、查询及导出结果验证业务；外部存储、媒体工具和算法边界可使用受控适配器模拟失败及延迟。前端通过用户操作、可见文本、按钮状态、录制与音频适配器验证行为。真实摄像头、锁屏、来电和音频体验以微信开发者工具及真机验证补充，不能仅凭模拟环境宣称通过。

### 既有测试基础

- 处方创建与立即生效的 API 测试已有动作参数、版本并发和权限场景，可扩展新参数及模式切换。
- 训练视频会话 API、发布并发、分片并发和视频处理测试已有上传、幂等及失败恢复场景，可复用验证逐组归属。
- 训练追踪、健康窗口和训练明细导出验收已有真实 API、工作簿内容及权限检查，可扩展按次汇总与逐组导出。
- 小程序运动流程、录像、缓存恢复、存储保护、页面及语音播放测试已有时间和设备适配器，可覆盖休息与多组队列。
- 医生端处方面板、动作分析面板、视频健康面板和追踪页面已有交互测试，可扩展表单及组明细。
- 独立分析服务已有动作插件与协议测试，重点确认每组输入独立、后踢合计口径和结果回写不影响父级计次，不重新验证与本需求无关的算法阈值。

### 必须通过的外部行为场景

1. 新开默认值、医生调整、无效参数、腿部后踢每侧含义正确；行走与认知游戏不回归。
2. 三个独立组视频关联同一次运动，各组均可单独分析；全部上传只计一次。
3. 只完成一至两组时为部分完成，保留有效组且不增加周完成次数。
4. 所有组做完但仍待上传时显示正确状态；上传全部成功即完成，分析仍可等待或失败。
5. 中途退出、切后台、来电或锁屏导致当前组重做，旧尝试清理和晚到请求不影响新尝试。
6. 当天续做、跨天返回、连续跨午夜、改方后重开、隔天及跨周补传都保持正确归属。
7. 休息满三分钟才能开始；时长、剩余组数、三十秒提醒、五秒倒数和滴答时机正确，结束不自动录像。
8. 休息时隐藏、恢复、音频失败或退出不会重置计时、补播过时语音或留下残留声音。
9. 多组待上传、慢网、上传失败、重启、暂存过期后补传及存储不足不造成覆盖、串组或虚报成功。
10. 重复点击、请求重试、重复发布和分析回调不重复建立有效组、视频、处方版本或完成次数。
11. 新处方开始后，旧处方已完成组仍可补传；旧处方不能继续追加新运动组。
12. 健康窗口与实际组时间一致，延迟上传不移动窗口，汇总时长不包含休息和重复取整。
13. 导出每组一行且可关联同次运动，部分完成状态清晰；作废历史排除，行走与游戏保持原状。
14. 迁移重复执行不重复创建版本；仅四动作旧记录作废，原始记录和录像可按权限查看。
15. 未改变的行走与游戏在自动版本迁移后保持既有参数与统计；项目结束、终止或解绑不被迁移重新激活。
16. 旧客户端新建旧模式请求被拒绝且提示可理解，旧会话收尾不会恢复正常计次。
17. 跨患者、跨账号、非法组序号、被放弃尝试和不匹配处方的请求被正确拒绝。
18. 演示具有一致交互，但不产生录像、上传或真实记录。

完成功能实施时运行相关后端、医生端、小程序全量测试及构建、静态检查、迁移检查和必要真机验证。本次 to-spec 只交付规格，不将文档检查描述为功能测试通过。

## Out of Scope

- 客户端同步动作识别、实时计数校验、实时纠错、等待分析返回才允许完成。
- 新增动作算法、训练模型或新设临床剂量建议。
- 改变行走为计数组模式，或改动认知游戏的执行与统计方式。
- 未完成组作为正式视频留存或参与分析；跨天返回拼接未完成组数；混用不同处方组数。
- 组间休息跳过、自动开始下一组、录制休息过程，或承诺锁屏期间持续声音。
- 删除作废旧训练的原始记录和录像，或者作废行走及游戏历史。
- 新增在线语音合成、全新素材运营系统或新的算法重新分析入口。
- 将录像传输分片当成运动组，或把三组视频计成三次完成。
- 修改项目绑定、患者归属、访问权限和解绑等既有业务规则。
- 本次规格发布不包含功能实现、生产迁移、提交、推送或上线。
