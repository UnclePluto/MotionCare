# 病人康复系统待讨论问题

> 状态：草稿
> 版本：0.3
> 更新日期：2026-08-20

## 已确认决策

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| D001 | 第一版范围 | 采用医院 Web 后台研究数据闭环版 |
| D002 | 小程序端 | 第一版后置，不作为本期必做 |
| D003 | 真实设备同步 | 已由 D029 覆盖；保留“不接 TCP”，改为接入厂商 OpenAPI |
| D004 | 患者模型 | 患者是全局基础档案，不依赖项目存在 |
| D005 | 患者池概念 | “患者池”只是全局患者列表的口语表达，不是业务对象 |
| D006 | 项目模型 | 系统支持多个医疗实验项目 |
| D007 | 项目配置 | 项目绑定 CRF 模板版本和访视计划 |
| D008 | 分组模型 | 分组属于项目，项目可有多个分组 |
| D009 | 分组比例 | 项目内分组配置比例，默认 1:1 |
| D010 | 随机分组 | 前端按项目分组比例临时计算；只有确认入组时才创建 `ProjectPatient` |
| D011 | 分组调整 | 分组确认前医生可人工调整，无需填写原因 |
| D012 | 分组锁定 | 分组确认后不可修改 |
| D013 | 新患者加入已存在项目 | 重新选择患者并在前端临时随机；确认入组后建立项目关系 |
| D014 | 访视状态 | 第一版仅支持草稿、已完成 |
| D015 | 访视流程 | 不做医生确认、质控、锁定流转 |
| D016 | 处方定位 | 处方是项目患者维度下的版本化训练计划 |
| D017 | 处方周期 | 第一版不设置计划周期和自动结束日期 |
| D018 | 处方调整 | 调整处方生成新版本，旧版本归档 |
| D019 | 处方生效 | 默认立即生效，也允许选择未来生效时间 |
| D020 | 处方动作 | 引用动作库并保存关键快照 |
| D021 | 训练录入 | Web 后台代患者录入训练数据 |
| D022 | 训练和处方版本 | 第一版只允许基于当前生效处方录入训练 |
| D023 | 历史训练补录 | 第一版不支持基于旧处方补录历史训练 |
| D024 | 训练类型 | 区分视频类、游戏互动类、运动类，但都用表单模拟 |
| D025 | 健康数据 | 已由 D030 覆盖；取消 Web 与小程序手工健康录入 |
| D026 | 健康日字段 | 已由 D031 覆盖；改为穿戴原始测量与计算生成的患者日汇总 |
| D027 | CRF 输出 | 支持 Web 预览、DOCX 导出、PDF 导出 |
| D028 | CRF 缺失策略 | 允许带缺失导出，Web 预览提示缺失，导出文件留空 |
| D029 | 穿戴接入方式 | 设备向厂商平台上报，MotionCare 每天 03:00 通过 OpenAPI 拉取；不接 TCP、Webhook |
| D030 | 健康数据来源 | 取消手工录入，心率、血压、血氧和步数仅来自穿戴同步 |
| D031 | 穿戴数据存储 | 保留原始测量点，按全局患者和自然日生成唯一日汇总；日内图表动态聚合 |
| D032 | 设备绑定 | 设备绑定全局患者，使用固定四位设备简码，按绑定/解绑时间区间隔离数据 |
| D033 | 穿戴补拉 | 按设备与指标同步历史动态确定窗口，每次最多回看七天 |
| D034 | 穿戴页面 | “训练追踪”升级为一级类目“训练与健康”，详情拆为“训练跟踪/穿戴健康”两个页签 |
| D035 | 穿戴与 CRF | 需求方确认 CRF 不包含健康信息；穿戴接入不得修改 CRF 模板、registry、预览或导出 |
| D036 | 项目研究窗口 | `StudyProject.completed_at` 为项目研究期上界；窗口采用 `[ProjectPatient.enrolled_at, completed_at)`，日汇总与项目聚合仅统计完整落入窗口的上海自然日 |
| D037 | 训练与健康医生范围 | 一期所有医生和管理员可查看全部已入组患者的训练、视频、分析与穿戴健康数据；保留可配置的既有行级过滤策略供后续恢复 |
| D038 | miwitracker 响铃 | `9018` 是平台级指令，不依赖型号、患者绑定或设备启停状态；响铃是停用设备唯一允许的远程命令例外 |
