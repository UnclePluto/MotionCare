# 病人康复系统 Spec Changelog

## 0.12 - 2026-08-05

- 肩部推举默认改为微信相机低分辨率档位，并在小程序端把每个录像分段压缩到最高 720P、约 2Mbps、24fps 后再上传。
- 训练视频单段上限从 32MB 调整为 50MB；删除完整视频累计大小上限，最长录像调整为 40 分钟，最多 80 个分段。
- 明确压缩前先持久化原始分段；压缩失败保留原始文件、暂停上传并允许重试，禁止直接上传未压缩分段。
- 患者首页取得的当前处方写入进程内共享缓存；处方页优先即时展示缓存并后台刷新，不再清空列表等待重复网络请求。
- 放宽长视频动作分析下载与 stale 时限，不升级现有依赖、基础镜像或运行环境。

## 0.11 - 2026-07-24

- 覆盖旧设计中“不记录项目完结时间”的限制：新增 `StudyProject.completed_at`，由项目完结动作首次写入并保持幂等。
- 明确项目患者的穿戴研究窗口为 `[enrolled_at, completed_at)`；原始点按精确时间裁剪，日汇总与项目/分组聚合仅统计完整落入窗口的 `Asia/Shanghai` 自然日。
- 明确项目完结不解绑设备、不停止同步且不删除历史数据；完结后新健康数据继续进入全局患者档案，但不进入已完结项目分析。

## 0.10 - 2026-07-23

- 覆盖旧决策“真实设备同步后置”：本期接入厂商 OpenAPI，设备继续向厂商平台上报，MotionCare 不接 TCP 或 Webhook。
- 覆盖旧决策“手工录入每日健康数据”：删除 Web 与微信小程序健康填报，健康数据仅来自穿戴设备同步。
- 明确设备使用固定四位简码绑定全局患者，绑定历史按开始/解绑时间隔离患者数据。
- 明确保留心率、血压、血氧原始测量点，并按患者和 `Asia/Shanghai` 自然日生成日汇总；日内图表动态聚合。
- 明确每天凌晨 03:00 同步，按设备与指标历史动态补拉，每次最多回看七天。
- 明确厂商整日步数在同日换绑时无法拆分，必须标记不可归属并排除，不能猜测或分摊。
- 将“训练追踪”升级为一级类目“训练与健康”，患者详情拆成“训练跟踪/穿戴健康”两个页签，页签名不展示设备在线标签。
- 明确需求方确认的 CRF 不包含健康信息；本次穿戴接入不得修改 CRF 模板、registry、预览、导出或缺失校验。

## 0.9 - 2026-07-14

- 纠正 0.8 中“小程序直传七牛”的错误记录：小程序每 30 秒生成分片并上传 MotionCare 业务服务器，业务服务器通过任务系统合并完整视频后再上传七牛。
- 明确七牛只保存最终完整视频，不接收训练分片；七牛上传成功后业务服务器删除全部视频临时文件。
- 明确分片上传失败不打断后续录像，失败分片进入手机本地重试队列；手机端在分片上传确认后立即删除对应本地文件。
- 明确训练总时长不设硬上限；页面隐藏时自动结束训练并进入收尾。
- 新增视频处理任务状态、幂等合并、失败重试与 48 小时临时文件保留/过期清理规则。
- 明确完整视频上传七牛、校验、重试和服务端清理由后台任务自动完成，患者端与医生端不提供任务管理页面。
- 视频任务增加单实例互斥、Celery 延迟确认、陈旧任务自动重投和运行中任务过期保护；患者端增加页面隐藏收尾、确认后本地清理恢复与异常启动恢复。

## 0.9 - 2026-07-11

- 覆盖 0.8 的“肩部推举视频由小程序单文件直传七牛”决策：微信小程序改为约 30 秒分段录制，在训练过程中逐段上传 MotionCare 单台业务服务器。
- 明确服务器使用 FFmpeg 合并任意合理数量的分段，优先无损转封装，不兼容时最多执行一次完整转码；不调用七牛 `avconcat` 或其它多媒体处理服务。
- 明确服务器只把最终 MP4 上传一次七牛；七牛对象校验和训练记录创建成功后立即删除本地文件，失败文件最多保留 24 小时。
- 明确强制上传页只等待所有分段安全到达服务器并成功提交处理任务，不要求患者等待 FFmpeg、七牛上传和 PP-TinyPose 分析完成。
- 明确一期按 Django Web 与 Celery/FFmpeg Worker 共享本机临时磁盘的单机部署设计，多机共享暂存不在本期范围。
- 增加七牛 attempt 隔离、canonical 发布和长期清理 tombstone，确保解绑、任务接管和迟到上传不会留下不可追踪对象。
- 增加录像尾段失败闭环、600 秒安全停止、FFmpeg/FFprobe 启动健康检查及 staging 0700 权限要求。

## 0.8 - 2026-07-08

- 覆盖旧决策“视频上传、AI 动作识别后置”：本里程碑先将肩部推举升级为小程序录像跟练、七牛 Kodo 直传、医生端视频审阅和手动触发动作分析。
- 明确肩部推举继续沿用 `ActionLibraryItem -> PrescriptionAction -> TrainingRecord` 主链路，不新建独立运动训练体系。
- 明确视频上传采用七牛 Kodo 上传凭证和小程序直传；后端只生成凭证、校验绑定、创建训练记录和生成私有下载 URL。
- 明确 PP-TinyPose 仅负责人体关键点检测，肩部推举计数和标准/不标准判定由 MotionCare 规则层完成。

## 0.7 - 2026-05-16

- 覆盖旧决策“真实游戏后置”：本里程碑开始在微信小程序落地两款真实认知小游戏（颜色顺序记忆、反应抑制能力训练）。
- 明确真实游戏一期继续沿用 `ActionLibraryItem -> PrescriptionAction -> TrainingRecord` 主链路，不新增 `GameSession` 后端模型。
- 明确小程序游戏需达到患者真实使用体验：适老化界面、海南康复主题、语音引导、音效、暂停/继续、提前结束、自动上传和结果页。
- 明确网络失败补传策略：缓存一条待上传训练记录；单次打开周期退避式重试最多 10 次；超过后下次打开小程序重新启动一轮 10 次重试。

- 明确患者详情去掉「打开 CRF」入口，CRF 入口保留在项目相关语境。

## 0.4 - 2026-05-11

- 明确"患者-项目绑定关系"仅在"分组内被确认"时才形成；删除一切"加入项目"的中间语义。
